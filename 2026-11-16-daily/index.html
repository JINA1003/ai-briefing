Claude Code 2.1.327: MCP 토큰을 명령줄 밖으로, `/status`에 고장 난 스킬 목록

한국 시간 11월 18일 아침 Claude Code 2.1.327이 나왔다. claude mcp add-json <name> -가 서버 JSON을 표준 입력으로 읽어, 토큰을 명령줄에 남기지 않고 MCP 서버를 등록한다(세션 안에서는 못 쓴다). /status는 고장 난 에이전트 · 스킬 · 명령 · 출력 스타일 파일, 키 바인딩 오류, 쓸 수 없는 샌드박스, 무시된 권한 설정, 절대 걸리지 않는 훅 매처를 목록으로 보여 준다. 프로젝트 범위 claude mcp add · remove가 .mcp.json의 $schema나 다른 도구 설정을 지우던 문제, Remote Control 워크트리 모드에서 서버를 멈추면 .env 같은 git 무시 파일이 지워지던 문제도 고쳤다. /export는 이제 기존 파일을 덮어쓰기 전에 묻는다.

그래서 무엇을 하나

업데이트한 뒤 /status를 한 번 열어 조용히 깨져 있던 스킬 · 훅이 있는지 본다. 토큰이 든 MCP 서버는 앞으로 표준 입력으로 등록한다.

  • 세션 밖 터미널에서 서버 설정 JSON 파일을 표준 입력으로 넘긴다: claude mcp add-json <이름> - < <서버설정.json>
  • Claude Code 세션에서 /status를 열고 고장 난 스킬 · 에이전트 · 훅 매처 목록을 확인한다.
  • /config에서 다른 설정에 덮인 항목은 이제 메모로 표시되니, 바꿨는데 안 먹던 설정이 있으면 거기서 확인한다.

MCP 공식 서버 v2.5.0: git · filesystem · everything 취약점 8개 추가 수정

지난주 v2.4.0에 이어 MCP 공식 참조 서버가 v2.5.0에서 취약점 8개를 고쳤다. mcp-server-git이 6개다. 병합 뒤 도는 git 자동 유지보수가 저장소 설정에 적힌 명령을 서버 권한으로 실행하던 문제, 조작한 .git/index로 작업 트리 밖 파일을 읽던 문제, 서브모듈 · 필터 드라이버가 명령을 실행하던 문제 등이다. server-filesystem은 폴더를 심볼릭 링크로 바꿔치기해 허용 폴더 밖 파일 이름이 보이던 문제를 고쳤다(Linux · macOS만, Windows는 아직). server-everything은 NAT64 주소로 사설 IP에 닿던 문제를 막았다.

그래서 무엇을 하나

Claude Code에 git · filesystem MCP 서버를 붙여 두었다면 이번 주에 버전을 올린다. filesystem 2.4.0은 패키지 관리자가 날짜 버전보다 낮게 보고 업그레이드로 제안하지 않으니 직접 지정해야 한다.

  • mcp-server-git을 2026.11.18로 올린다.
  • 날짜 버전 filesystem 서버를 쓰고 있었다면 npm install @modelcontextprotocol/server-filesystem@2.4.0처럼 2.4.0을 직접 지정한다.
  • @modelcontextprotocol/server-everything은 2.3.1로 올린다.
  • .mcp.json · 설정 파일에서 버전 없이 띄우는 서버가 있으면 실제로 어떤 판이 깔리는지 확인한다.

SkillEvaluator (NVIDIA, 스킬 채점 · 로드 검사)

무엇인가

에이전트 스킬 · 플러그인의 품질, 보안, 호환성을 세 단계로 검사하는 도구다. 1단계는 품질 · 스키마 · 개인정보 · 라이선스 · 유니코드 · 스크립트 · 보안을 정적으로 보고, 별도의 harness-check로 Claude Code · Codex 등이 그 스킬을 실제로 읽어 들이는지 본다. 2단계는 스킬끼리 겹치는 지침을 찾고, 3단계는 스킬을 켠 실행과 끈 실행을 비교해 효과를 잰다. 전에는 스킬을 만들면 몇 번 써 보고 감으로 판단했다. 이제는 맞춤법 검사기처럼 점수와 감점 이유를 받고, 읽히지 않는 스킬도 미리 걸러 낸다.

왜 지금

11월 18일 v1.0.1이 1.0 계열의 첫 완성판으로 나왔다(PyPI 패키지 · CI 묶음 포함). 지난 7일 중 2일 GitHub 일간 트렌딩에 올랐다. 이번 판에서 여섯 하네스(codex, claude-code, opencode, hermes, openclaw, copilot-cli) 호환성을 보는 HarnessCheck가 들어왔다.

설치

pip install skillevaluator

활용법

  1. skillevaluator quality-check ./<내 스킬 폴더>로 100점 만점 점수, 등급, 감점 이유를 본다. 통과선은 기본 70점이다.
  2. skillevaluator harness-check ./<내 스킬 폴더>로 하네스별로 스킬이 읽히는지(loads · degraded · not loaded)와 그 이유를 본다. API 키와 에이전트 실행이 필요 없다.
  3. GitHub 저장소에서 skillevaluator ci init을 돌리면 스킬 검사 설정 PR이 열린다. 검사 항목을 고르고 PR을 검토한다.
  4. 에이전트에게 맡기려면 npx skills add NVIDIA/SkillEvaluator로 스킬을 넣고 "Is my skill any good?"처럼 묻는다.

예시 프롬프트

SkillEvaluator로 ~/.claude/skills/<스킬 이름> 폴더를 검사해 줘. quality-check와 harness-check만 돌리고, 감점 항목과 claude-code에서 안 읽히는 이유를 고칠 순서대로 정리해 줘. 파일은 아직 고치지 마.

주의. quality-check와 1단계, harness-check는 API 키 · GPU · Docker 없이 돈다. 2 · 3단계는 모델 공급자 키가 필요하고, README는 모델 · 관리형 샌드박스 사용에 요금이 붙을 수 있다고 적었다. 3단계는 기본으로 Docker가 필요하다(--tiers 1,2로 건너뛴다). 정적 검사를 다 하려면 Gitleaks · Bandit 같은 외부 스캐너가 있어야 하고, 없으면 INCOMPLETE로 끝난다. Python 3.12~3.14가 필요하다. 실험(Experimental) 단계이고 지원은 SLA 없는 best-effort다.

  3. 이미 있는 페이지는 브라우저 점검 결과를 먼저 받고 고칠 곳을 고른다.

예시 프롬프트

Claude Code 2.1.326: 에이전트 팀에서도 Code Mode, bypass 모드도 일부는 다시 묻는다

11/16 나온 Claude Code 2.1.326은 변경 항목이 아주 많은 판이다. 에이전트 팀을 켠 채로 실험 기능 Code Mode를 쓸 수 있게 됐다(팀원은 기본 in-process 표시 모드에서만 Code Mode로 돈다). 권한 쪽은 더 조였다. bypass permissions 모드에서도 일부 도구 호출은 묻거나, 물을 사람이 없으면 거절한다. 훅의 "decision": "block"이 더 많은 경우에 지켜져서, 늘 block을 출력하던 훅이 실제로 막기 시작할 수 있다. 샌드박스 명령은 기본으로 일부 민감한 홈 폴더에 쓰지 못한다. 그 밖에 /status에 공급자나 DISABLE_TELEMETRY 같은 변수 때문에 꺼진 기능을 알려 주는 줄이 생겼고, opusplan일 때 계획 모드 자동 압축이 답하는 모델(Opus 등)로 돌아 비용이 늘 수 있다. /claude-api 스킬은 이제 기본으로 Managed Agents 위에 에이전트를 만든다.

그래서 무엇을 하나

우리 팀에게는: bypass 모드나 훅으로 굴리던 밤 작업 · 예약 작업이 업데이트 뒤 확인 창에서 멈추거나 거절될 수 있다. → 업데이트 후 /status를 보고, 늘 block을 내는 훅이 없는지 확인하고, 무인 작업 하나를 한 번 돌려 본다.

  • claude --version으로 판을 확인하고, 2.1.326보다 낮으면 claude update를 실행한다.
  • /status에서 새로 생긴 줄을 보고, 공급자나 환경 변수 때문에 꺼진 기능이 있는지 확인한다.
  • 훅 설정에서 조건 없이 "decision": "block"을 출력하는 훅을 찾아, 막아야 할 때만 출력하게 고친다.
  • 샌드박스 명령이 홈 폴더에 못 쓰게 되면 사용자 설정의 sandbox.filesystem.allowWrite에 필요한 경로만 더한다.
  • 에이전트 팀과 Code Mode를 함께 쓰려면 CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 claude로 시작한다. 팀원 화면을 분할 창(split panes)으로 두면 팀원은 Code Mode 없이 시작한다.
  • opusplan을 쓰면 계획 모드 자동 압축도 Opus로 돌아 비용이 늘 수 있으니 /usage로 지켜본다.

security-audit (Cloudflare 보안 감사 스킬)

무엇인가

코딩 에이전트를 보안 감사자로 바꾸는 스킬이다(MIT). 정찰로 구조 · 신뢰 경계 · 입력 지점을 정리하고, 격리된 탐색 에이전트들이 나눠 맡은 곳을 뒤진다. 찾은 후보는 새 검증 에이전트가 반박을 시도하고, 살아남은 것만 confirmed로 남겨 REPORT.md 등으로 낸다. README는 Cloudflare 취약점 탐지 체계의 단일 저장소판 출발점이라고 소개한다.

왜 지금

별 상위 저장소 가운데 지난 7일 별 증가가 세 번째로 컸다(+5,137, 누적 73,240). skills.sh 설치 수는 11.16만이다. 같은 저장소에 다시 돌리면 이전 기록을 이어받아 빈 곳만 더 파는 누적 방식이다.

설치

npx skills add https://github.com/cloudflare/security-audit-skill --skill security-audit

활용법

  1. 전: 「보안 문제 찾아 줘」라고 하면 한 대화가 훑고 그럴듯한 목록을 냈고, 진짜인지는 사람이 다시 봤다. 후: 찾는 에이전트와 반박하는 에이전트가 나뉘어, 검증을 통과한 것(confirmed), 더 확인할 것(needs_validation), 기각된 것(rejected)으로 나뉜 보고서가 나온다.
  2. README의 예시 문장 그대로 시작한다: security audit this codebase 또는 find security vulnerabilities in ./src.
  3. 출력 폴더를 정하지 않으면 ~/security-audit-skill/<repo-name>/run-<N>에 쌓인다. 저장소 안에는 git이 무시하는 폴더를 직접 고를 때만 쓴다.
  4. README는 한 번 실행이 여러 번 실행에서 찾은 것의 절반쯤만 찾았다고 적는다. 같은 저장소에 두세 번 돌려 결과를 누적한다.

예시 프롬프트

security-audit 스킬로 이 저장소의 보안 감사를 해 줘. 결과는 ~/audits/<프로젝트 이름>에 쓰고, 끝나면 confirmed 항목만 심각도 순으로 요약해 줘.

주의. 도구 호출과 병렬 서브에이전트를 지원하는 에이전트 · 모델이 필요하고, 검증기 실행에 Node.js가 필요하다. 대상 코드를 빌드 · 실행하려면 외부 네트워크 차단, 정리된 환경 변수, 자원 제한, 쓰기 경로 제한을 갖춘 OS 수준 샌드박스가 있어야 한다. 없으면 대상 코드를 실행하지 않고 후보를 needs_validation으로 남긴다. 에이전트를 여럿 병렬로 돌리는 구조라 토큰을 많이 쓸 수 있다(README에 비용 수치는 없다). skills.sh 보안 점검에서 Snyk는 Warn이다.

Open Code Review (Alibaba 코드 리뷰 도구)

무엇인가

Alibaba가 공개한 AI 코드 리뷰 CLI다(Apache-2.0). git diff에서 바뀐 파일을 고르고 관련 파일을 묶는 일은 정해진 파이프라인이 하고, 맥락을 찾아 판단하는 일은 LLM 에이전트가 한다. 결과는 줄 단위 코멘트로 나온다. ocr scan은 diff가 아니라 파일 전체를 본다. Claude Code 플러그인과 다른 에이전트용 스킬도 있다.

왜 지금

지난 7일 중 3일 GitHub 일간 트렌딩에 올랐고 지난주 별이 2,238개 늘었다. Alibaba 자체 벤치마크(오픈소스 저장소 50개, PR 200개, 10개 언어, 정답 이슈 1,505개)에서 같은 모델의 Claude Code보다 정밀도 · F1이 높고 토큰은 약 9분의 1이라고 한다. 대신 재현율은 낮고, 이는 일부러 고른 것이라고 밝힌다.

설치

npm install -g @alibaba-group/open-code-review

활용법

  1. 전: Claude에게 「이 PR 리뷰해 줘」라고 하면 일반론이 섞인 긴 답과 헛짚은 지적이 함께 왔다. 후: 바뀐 줄에 붙는 짧은 코멘트 위주로 나와, 고칠 곳을 바로 찾는다.
  2. Claude Code 안에서는 /plugin marketplace add alibaba/open-code-review, /plugin install open-code-review@open-code-review로 플러그인을 넣는다.
  3. 따로 API 키를 두기 싫으면 위임 모드 /open-code-review:delegate-review를 쓴다. 파일 고르기와 규칙은 OCR이, 리뷰는 Claude Code의 모델이 한다.
  4. 기본 모드는 ocr config provider, ocr config model로 모델을 정한 뒤 ocr review로 돌린다.

예시 프롬프트

/open-code-review:delegate-review 로 지금 브랜치의 변경을 리뷰해 줘. 그다음 같은 변경을 네가 직접 리뷰한 결과와 비교해서, 한쪽만 찾은 지적을 표로 정리해 줘.

주의. 기본 모드(ocr review, /open-code-review:review)는 OCR에 따로 설정한 공급자로 모델을 부르고, Claude Code 구독 로그인을 쓰지 않는다. 그 공급자 요금이 든다. Git 2.41 이상이 필요하다. 벤치마크는 Alibaba가 직접 낸 것이고 재현율이 낮다고 스스로 밝히므로, 놓치는 문제가 있다는 전제로 쓴다. README는 어떤 코드가 어디로 가는지 자세히 적지 않는다.

Claude Code 2.1.325: 샌드박스 Bash도 다시 묻고, 실험 기능 Code Mode를 손봤다

11/13 나온 Claude Code 2.1.325는 권한 동작 두 가지를 바꿨다. 샌드박스 안의 Bash 명령도 이제 기본으로 일반 권한 확인을 거친다. 예전처럼 묻지 않게 하려면 sandbox.autoAllowBashIfSandboxed: true를 둔다. 예약 작업과 /loop은 allowed-tools나 훅을 선언한 스킬을 돌리기 전에 묻는다. 바로 앞 2.1.323(11/12)에 나온 실험 기능 Code Mode(Claude가 JavaScript를 써서 도구 여러 개를 한 번에 부른다)의 버그도 여럿 고쳤고, zstd 응답 해석의 보안 문제와 서브에이전트 모델 선택 버그도 고쳤다.

그래서 무엇을 하나

우리 팀에게는: 업데이트 뒤 샌드박스 작업에서 확인 창이 늘거나, 밤에 돌던 /loop · 예약 작업이 스킬 앞에서 멈춰 있을 수 있다. → 무인 작업에 쓰는 스킬을 permissions.allow에 Skill(이름)으로 등록하고, 여러 파일에 같은 수정을 하는 일에 Code Mode를 한 번 시험한다.

  • claude --version으로 2.1.325 이상인지 확인하고, 아니면 claude update를 실행한다.
  • 샌드박스 Bash를 예전처럼 묻지 않게 하려면 설정에 sandbox.autoAllowBashIfSandboxed: true를 넣는다.
  • 예약 작업 · /loop에서 스킬을 묻지 않고 돌리려면 permissions.allow에 Skill(<스킬 이름>)을 더한다.
  • Code Mode는 CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 claude로 시작하고, 처음 묻는 창에서 「Yes, turn on Code Mode」를 고른다.
  • Claude가 쓴 코드는 Ctrl+O로 기록 화면을 열고 Code 줄을 펼쳐 본다.
  • Code Mode 세션을 claude --continue로 이어 열 때도 변수를 1로 둔다. 끄면 그 세션을 이어 열 수 없다.
  • Code Mode 제약: 터미널의 대화형 claude에서만 된다(-p · SDK · VS Code · 데스크톱 앱 불가). 게이트웨이 · Bedrock · Foundry 경유, DISABLE_TELEMETRY, 에이전트 팀이 켜져 있으면 시작하지 않는다. 기다리는 코드는 10분에 멈춘다.

OpenRig (에이전트 팀을 상주시키기)

무엇인가

OpenRig는 여러 코딩 에이전트 세션을 역할 · 공유 맥락 · 맡은 일이 있는 한 팀으로 묶어 계속 돌리는 오픈소스다(Apache 2.0). 팀 구성은 RigSpec이라는 YAML에 적고, rig up이 tmux 세션들을 띄우고 시작 파일 적용과 준비 점검까지 한다. Claude Code와 Codex를 한 팀에 섞을 수 있고, pi는 RPC 러너로 붙는다.

왜 지금

11/15에 받은 「Claude Code에 붙이는 오픈소스 4개」 중 하나다. 지금 README의 설치 명령은 v0.7.16 기준이다(제보 이미지의 v0.6.1보다 새 판). 「Claude 로그인 하나면 된다」는 팀원이 모두 Claude Code일 때만 맞고, README는 Claude Code나 Codex 중 하나만 로그인돼 있으면 된다고 적는다. 「2~7명 템플릿」은 README에서 확인하지 못했다. 대신 starter · workshop · factory와 code-review · research · pm 같은 내장 팀이 있다.

설치

npm install -g @openrig/cli

활용법

  1. 전: 터미널 창 서너 개에 Claude를 따로 열고, 창마다 할 일을 손으로 나눠 붙여 넣었다. 후: 리드 에이전트에게만 말하면 구현 담당 · 검토 담당에게 일이 나뉜다.
  2. 먼저 rig setup --dry-run으로 무엇을 바꾸는지 본다. 바뀌는 파일은 미리 백업한다.
  3. 내장 팀 starter로 시작하고, 익숙해지면 code-review 같은 전문 팀을 써 본다.
  4. Superpowers와 비교: Superpowers는 에이전트 하나가 「묻기 → 계획 → TDD → 작업마다 새 서브에이전트 + 2단계 리뷰」 순서로 일하게 하는 스킬 묶음이다. OpenRig는 그 바깥의 상주 팀이다. 겹치는 곳은 OpenRig의 구현 · 검토 담당과 Superpowers의 서브에이전트 리뷰 정도라 둘을 함께 쓸 수 있다.

예시 프롬프트

OpenRig README를 읽고 이 저장소에 맞는 RigSpec 초안을 만들어 줘. 리드 1명, 구현 1명, 검토 1명으로 하고, 실행 전에 바뀌는 설정 파일 목록부터 보여 줘.

주의. 설정 · 실행 때 ~/.tmux.conf, ~/.claude.json, ~/.codex/config.toml, AGENTS.md · CLAUDE.md, 훅 설정을 고친다. README는 이 파일들을 보존하거나 되돌린다고 보장하지 않으니 먼저 백업한다. Node.js 22 또는 24와 tmux가 필요하다. workshop 팀은 권한이 넓다. 활발히 개발 중인 0.x 판이다.

Hindsight (저장소별 장기 기억)

무엇인가

Hindsight는 에이전트가 지난 대화를 떠올리는 데서 그치지 않고 시간이 지나며 배우게 하는 오픈소스 기억 시스템이다(MIT). 코딩 에이전트용 패키지는 git 기록과 지난 세션으로 저장소마다 기억 은행을 자동으로 만들고, 작업을 시작할 때 그 맥락을 넣어 준다. 구조 · 규칙 · 진행 중인 일을 정리한 페이지도 따로 관리한다.

왜 지금

11/15 제보다. 제보 이미지의 「교정 57% 감소」는 README에서 찾지 못해 확인 안 됨이다. README가 내세우는 근거는 LongMemEval 벤치마크(2026년 1월 기준 최고 성적, 외부 기관 재현)다. 11/02 판에 실린 claude-mem과 하는 일이 겹친다.

설치

npx @vectorize-io/hindsight-coding-agents install claude-code

활용법

  1. 전: 새 세션마다 「이 저장소는 이런 규칙이야」를 다시 설명하거나 CLAUDE.md를 손으로 늘렸다. 후: 지난 세션과 커밋에서 뽑은 규칙 · 진행 중인 일이 세션 시작 때 들어온다.
  2. 설치 전에 ~/.claude/settings.json을 백업하고, 설치 뒤 무엇이 바뀌었는지 비교한다.
  3. 기억을 만들 LLM이 필요하다. API 키를 넣거나 Ollama 같은 로컬 모델을 고른다.
  4. claude-mem을 이미 쓰고 있다면 둘을 같이 켜지 말고, 한 저장소에서 하나씩 써 보고 고른다.

예시 프롬프트

Hindsight가 이 저장소에 대해 기억하는 규칙과 진행 중인 일을 보여 줘. 틀린 것이 있으면 어느 세션이나 커밋에서 나왔는지도 알려 줘.

주의. 기억을 만들 때 LLM을 부르므로 API 비용이 든다. 로컬 모델을 쓰면 피할 수 있다. 권장 실행 방식은 Docker이고, Intel Mac은 hindsight-all-slim을 쓰라고 한다. 기억을 만들 때 저장소 내용이 설정한 LLM 공급자에게 가므로 사내 저장소는 공급자를 먼저 정한다.

MinerU (문서를 AI가 읽는 마크다운으로)

무엇인가

MinerU는 PDF · Office · 스캔 이미지 같은 복잡한 문서를 LLM이 읽기 좋은 마크다운 · JSON으로 바꾼다. 저장소에 공식 mineru 스킬이 생겨, 에이전트가 문서를 페이지나 블록 단위로 이어 읽고 인용용 위치표(doc:…/page:…/block:…)를 남긴다. 최신은 MinerU 4.2다.

왜 지금

11/15 제보다. 제보 때는 「공식 스킬 없음, 커뮤니티 래퍼만」이었지만 지금 README에는 공식 스킬과 설치 명령이 있다. 「페이지 단위로 이어 읽고 출처를 남긴다」도 README의 에이전트 안내에서 확인했다.

설치

npx skills add opendatalab/MinerU --skill mineru --global --yes

활용법

  1. 전: 스캔 PDF를 통째로 올리면 표가 깨지거나 긴 문서는 앞부분만 읽혔다. 후: 페이지 · 블록 단위로 나눠 읽고, 답마다 몇 쪽 어느 블록인지 위치가 붙는다.
  2. 스킬 없이 직접 쓸 때는 mineru-kit parse document.pdf -o document.md --tier standard로 바꾼다.
  3. 가벼운 문서는 basic 단계(RAM 2GB), 표 · 수식이 많으면 standard 이상(RAM 8GB)을 쓴다.

예시 프롬프트

mineru 스킬로 <파일 경로>를 마크다운으로 바꾸고, 표가 있는 페이지만 골라 요약해 줘. 요약 문장마다 위치표를 붙여 줘.

주의. 기본은 로컬 처리이고, --remote를 붙일 때만 문서가 원격 파싱으로 간다. 사내 문서에는 --remote를 쓰지 않는다. 텔레메트리가 처음에 켜져 있다(문서 내용 · 파일명은 빠진다고 한다). mineru telemetry disable 또는 MINERU_TELEMETRY_DISABLED=1로 끈다. 라이선스는 Apache 2.0에 조건을 더한 MinerU 자체 라이선스다. 커뮤니티 래퍼 중 일부는 문서를 MinerU 호스팅 API로 보내니 공식 스킬을 쓴다.

Plannotator (계획 · 코드 리뷰를 브라우저에서)

무엇인가

Plannotator는 코딩 에이전트의 계획 · 문서 · 코드 변경을 브라우저에서 보며 메모를 달고, 그 메모를 에이전트에게 돌려보내는 로컬 도구다. Claude Code가 계획 모드를 끝낼 때(ExitPlanMode) 훅이 계획을 브라우저에 연다. 승인하거나 메모와 함께 거절하면 Claude가 계획을 고치고, 바뀐 곳은 diff로 보인다. /plannotator-review로 커밋 전 변경이나 PR도 줄 단위로 리뷰한다.

왜 지금

GitHub 트렌딩에 올라 지난주 별이 818개 늘었다. 텔레메트리를 모으지 않는다고 밝히고, Apache 2.0 또는 MIT 중 고르는 이중 라이선스다.

설치

/plugin marketplace add backnotprop/plannotator

활용법

  1. 전: 계획 모드의 긴 계획을 터미널에서 읽고 「3번은 빼고 5번은 이렇게」를 다시 타이핑했다. 후: 브라우저에서 그 줄에 바로 메모하고 거절하면, 메모가 정리된 피드백으로 Claude에게 간다.
  2. README 순서대로 curl -fsSL https://plannotator.ai/install.sh | bash, 위 명령, /plugin install plannotator@plannotator를 실행하고 Claude Code를 재시작한다.
  3. /plannotator-last로 Claude의 마지막 답에도 메모를 단다.
  4. /plannotator-review <PR 주소>로 PR을 리뷰하고 줄 메모를 Claude에게 넘긴다.

예시 프롬프트

이 기능을 계획 모드로 먼저 설계해 줘: <기능 설명>. 단계마다 바꿀 파일과 돌릴 테스트를 적어 줘.

주의. 작은 공유 링크는 URL에 압축만 되고 암호화되지 않아, 링크를 가진 누구나 읽는다. PLANNOTATOR_SHARE=disabled로 공유를 끈다. 리뷰 화면을 열 때마다 GitHub에서 새 판을 확인하며, 이 확인은 끌 수 없다.

설치

npx -y loopforge-cli@latest install claude

예시 프롬프트

이 저장소에서 SOP로 만들 만한 반복 작업 세 개를 골라 줘. 각각 어느 단계에 사람 승인을 둘지도 적어 줘.

주의. 에이전트 단계에는 모델 API 키가 필요하고, 비용은 연결한 서비스 요금대로다. 내장 역할의 기본 실행기는 CodeBuddy라서 Claude Code를 쓰려면 역할마다 실행기를 바꾼다.

  2. 서버 없이 돌리려면 저장소를 fork하고 API 키 · 종목 목록을 Secrets에 넣은 뒤 GitHub Actions를 켠다(평일 베이징 시각 18:00 실행).

예시 프롬프트

이 저장소의 GitHub Actions 워크플로를 읽고, 한국 시장 종목만 Claude로 분석해 Discord로 보내려면 어디를 바꾸면 되는지 알려 줘.

주의. README는 학습 · 연구용이며 투자 조언이 아니라고 밝힌다. 기본 데이터 소스(AkShare · YFinance 등)는 무료지만 안정성이 보장되지 않는다. LLM 호출 비용은 쓰는 키의 요금대로다.

Sure (Maybe Finance를 잇는 개인 재무 앱)

무엇인가

Sure는 보관 처리된 Maybe Finance를 커뮤니티가 이어 가는 개인 재무 앱이다(AGPLv3). 브라우저 · macOS 앱 · 모바일 앱 · API와 LLM 에이전트에서 쓸 수 있다. 원클릭 배포에는 OpenAI 토큰으로 켜는 「Simple AI」와 외부 게이트웨이에 붙는 「External AI」 구성이 있다.

왜 지금

11/13 제보 순위 2위(+1,078)였다. 제보 때는 AI 기능이 있는지 확인되지 않았는데, README에서 AI 도우미 구성을 확인해 싣는다. AI 기능이 무엇을 하는지는 README에 자세히 없다.

설치

bin/setup

활용법

  1. 전: 은행 · 카드 내역을 엑셀에 모아 손으로 분류했다. 후: 내 서버에 내역을 모으고 AI 도우미에게 지출을 묻는다.
  2. 가장 쉬운 길은 README의 Docker 안내(docs/hosting/docker.md)나 원클릭 배포다.
  3. 개발 환경은 Ruby · PostgreSQL · Redis가 필요하다. cp .env.local.example .env.local, bin/setup, bin/dev 순서로 띄우고 http://localhost:3000을 연다.

예시 프롬프트

Sure 저장소에서 AI 도우미 관련 코드와 `compose.example.ai.yml`을 읽고, AI를 켜면 어떤 데이터가 OpenAI로 가는지 정리해 줘.

주의. Simple AI 구성은 OpenAI 토큰을 쓰므로, 켜기 전에 어떤 금융 데이터가 OpenAI로 가는지 확인한다. 셀프 호스팅이라 접근 제한과 백업은 직접 챙긴다. AGPLv3라 고쳐서 서비스로 내면 소스를 공개해야 한다.
