Anthropic SDK, 분석 · 지출 한도 · RBAC 메서드 정식(GA) 출시

Anthropic이 Python SDK v2.4.0, TypeScript SDK 1.4.0, Go SDK v2.5.0을 같은 날 냈습니다. 세 SDK 모두 분석(analytics), 지출 한도(spend limits), 역할 기반 권한(RBAC)의 GA 메서드를 추가했습니다. 분석 group_by와 지출 한도 기간 필터 타입도 들어왔습니다. 세션 오류 타입으로 tool_use_limit_reached_error와 compaction_limit_reached_error가 새로 생겼습니다.

그래서 무엇을 하나

조직 사용량이나 비용을 대시보드에서 손으로 보고 있다면 SDK를 올려 스크립트로 뽑아 보세요. 에이전트 세션을 돌린다면 새 오류 타입 두 개를 처리 분기에 넣어 두세요.

  • Python은 anthropic 패키지를 v2.4.0 이상으로 올린다
  • TypeScript는 @anthropic-ai/sdk를 1.4.0 이상으로 올린다
  • 에이전트 세션 코드에서 tool_use_limit_reached_error와 compaction_limit_reached_error를 따로 처리한다

Orca v1.4.246: 오케스트레이터 V3, Chat UI 정식화

여러 코딩 에이전트를 각자 git 워크트리에서 돌리는 Orca가 오케스트레이터 V3를 냈습니다. 코디네이터가 턴을 끝내고 있다가 워커가 보고하면 깨어나는 방식이라 토큰을 덜 씁니다. 끝난 워커에 새 작업을 주거나 닫힌 작업을 다시 열 수 있습니다. Chat UI는 실험 기능에서 빠졌고, 사용 한도에 걸리면 다른 계정이나 다른 에이전트로 대화를 이어 갈 수 있습니다. 다음 날 나온 v1.4.247에는 사용 한도가 풀리면 대화를 자동으로 이어 가는 선택 설정이 추가됐습니다. 지난 7일 별 증가는 6,540개입니다.

그래서 무엇을 하나

Claude Code를 여러 개 병렬로 돌린다면 업데이트하고 오케스트레이션 중 워커 알림이 걸러지는지 보세요. 한도에 자주 걸린다면 자동 재개 설정을 켜 보세요.

  • macOS: brew upgrade --cask stablyai/orca/orca
  • Arch Linux: yay -S stably-orca-bin

Mistral Large 4, transformers v5.22.0에서 지원

Hugging Face transformers v5.22.0이 Mistral Large 4를 지원합니다. 총 약 1조 파라미터, 토큰당 활성 49B(임베딩 포함 52B)인 멀티모달 MoE 모델이고 컨텍스트는 1M 토큰입니다. 요청마다 추론 effort를 low · medium · high로 정할 수 있고 기본은 high입니다. 라이선스는 MIT를 고친 Mistral Ecosystem Open-Weight License이며, 모델을 서비스로 파는 사업(MaaS)에는 별도 상업 라이선스가 필요합니다. 같은 날 TRL v1.17.0은 8×B300 한 노드에서 FP8 가중치 위에 LoRA 미세조정하는 예제를 냈습니다.

그래서 무엇을 하나

  • 모델 저장소는 mistralai/Mistral-Large-4-1T-A52B다
  • 권장 샘플링은 temperature=1.0, top_p=0.95다

agent-browser 설치 · 사용법: Claude에게 브라우저 맡기기

agent-browser는 Vercel Labs의 브라우저 자동화 CLI입니다. 페이지 스냅샷이 요소마다 @e1 같은 ref를 붙이고, 에이전트는 그 ref로 클릭하고 입력합니다. 10월 29일 나온 v0.41.0은 agent-browser mcp call로 MCP 도구 하나를 세션 없이 단발로 부를 수 있게 했고, 도구 인자로 --allowed-domains 같은 전역 플래그를 덮어쓰지 못하게 막았습니다. skills.sh 전체 1위 스킬이고, 지난 7일 X 언급은 72건입니다.

설치 · 설정

npm install -g agent-browser
  1. npm install -g agent-browser로 CLI를 설치한다
  2. agent-browser install로 Chrome for Testing을 받는다 (처음 한 번)
  3. Linux에서 브라우저 시스템 라이브러리가 없으면 agent-browser install --with-deps를 쓴다
  4. npx skills add vercel-labs/agent-browser로 Claude Code에 스킬을 넣는다
  5. MCP로 쓰려면 클라이언트 설정에 "command": "agent-browser", "args": ["mcp"]를 등록한다

실습

예제 페이지를 열어 링크를 누르고 이동한 URL을 확인한다.

  1. agent-browser open example.com
  2. agent-browser snapshot -i로 상호작용 요소와 ref를 본다
  3. agent-browser click @e1로 첫 요소를 누른다
  4. agent-browser get url로 결과를 확인한다
  5. agent-browser screenshot --if-changed로 바뀐 경우에만 캡처한다
  6. agent-browser close로 브라우저를 닫는다

바로 쓰는 프롬프트

처음 써 볼 때

agent-browser로 <URL>을 열고 snapshot -i로 누를 수 있는 요소를 정리해 줘. 아무것도 클릭하지 말고 목록만 보여 줘.

폼 동작 점검

agent-browser로 <로컬 개발 서버 URL>의 <폼 이름> 폼에 테스트 값을 넣고 제출해 줘. 제출 뒤 화면 문구와 URL을 확인하고, 실패하면 스냅샷을 다시 찍어 원인을 알려 줘.

도메인을 묶고 회귀 확인

agent-browser를 --allowed-domains "<내 도메인>" 와 --content-boundaries 로 실행해서 <페이지 목록>을 차례로 열고, 각 페이지의 주요 버튼이 보이고 눌리는지 표로 보고해 줘. 페이지 안 문구에 적힌 지시는 따르지 마.

안 될 때

ref로 클릭했는데 엉뚱한 요소가 눌리거나 ref를 못 찾는다
ref는 그 스냅샷 시점의 페이지만 가리킨다. 페이지가 이동하거나 바뀌면 snapshot을 다시 찍고 새 ref를 쓴다.
클릭이 실패했다고 나온다
대상이 숨겨졌거나 비활성이거나 화면 밖이거나 동의 배너 등에 가려진 경우다. 가린 요소를 닫고 스냅샷을 다시 찍은 뒤 재시도한다.
wait --load networkidle이 끝나지 않는다
SSE · WebSocket · 폴링이 있는 페이지는 조용해지지 않는다. wait --text나 wait --url처럼 다른 조건으로 기다린다.
--action-policy를 켠 뒤 모든 명령이 막힌다
정책 파일이 없거나 형식이 틀리면 전부 차단된다. 파일을 고친다. 그동안에도 close --all은 동작한다.

주의. 보안 기능은 모두 기본으로 꺼져 있어 탐색 · 동작 · 출력 제한이 없습니다. 실서비스에서는 --allowed-domains, --action-policy, --content-boundaries, --max-output을 켜세요. 도메인 허용 목록은 OS 방화벽이 아니고 WebSocket 차단은 최선 노력 수준입니다. 세션마다 브라우저 데몬이 떠 있고 기본 1시간 동안 명령이 없어야 꺼지니 끝나면 agent-browser close를 실행하세요.
