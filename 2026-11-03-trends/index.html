Claude Code 2.1.317: 예약 작업 커넥터 경고, 이메일 전송 전 확인, SDK 훅 실패 시 차단

새 클라우드 예약 작업에 요청하지 않은 커넥터가 붙으면 /schedule이 경고하고 빼는 방법을 알려 줍니다. 웹 · 셸 도구가 계정 이메일 주소를 네트워크로 보내기 전에 묻는 확인도 생겼습니다. Agent SDK 훅 콜백에 onFailure: "block"을 주면 콜백이 실패할 때 동작을 막습니다. Read 도구의 "unchanged" 축약이 없어져, 바뀌지 않은 파일을 다시 읽어도 내용이 돌아옵니다. /loop 깨우기가 예약되지 않던 문제도 고쳐졌습니다.

그래서 무엇을 하나

/schedule로 만든 작업이 있다면 커넥터 목록을 열어 필요 없는 것을 뺍니다. SDK 훅으로 검사를 걸어 두었다면 onFailure: "block"을 붙여 검사 실패가 그냥 통과되지 않게 합니다.

  • /schedule update로 기존 예약 작업의 커넥터를 확인하고 쓰지 않는 것을 뺀다.
  • Agent SDK 훅 콜백 설정에 onFailure: "block"을 추가한다.
  • self-hosted runner에서 예전처럼 claude -p가 바깥 세션 ID를 쓰게 하려면 CLAUDE_CODE_DISABLE_NESTED_SESSION_ID=1을 설정한다.

Anthropic S-1: 9월 새 코드의 90% 이상을 Claude가 작성

외부 측정 · 보도Anthropic 상장 신고서(S-1)를 바탕으로 Business Insider가 내부 AI 사용 규모를 보도했습니다. 9월 내부 사용량은 1월의 250배를 넘었고, 9월에 새로 추가된 코드의 90% 이상을 Claude가 썼습니다. 4월에는 내부 사용량을 고객 요금으로 환산한 값이 주식 보상을 뺀 한 달 직원 보수를 넘었습니다. 실제 현금 지출이 아니라 판매가로 환산한 값이라는 점은 HN에서도 논란이 됐습니다.

그래서 무엇을 하나

숫자 자체보다 "새 코드 대부분을 AI가 쓰고 사람은 검토한다"는 분업이 회사 단위로 굳어지고 있다는 신호로 읽습니다. 내 작업에서 AI가 쓰는 몫과 내가 검토하는 몫을 나눠 적어 봅니다.

Postgres 19 출시 지연: LLM이 버그를 찾는 속도를 수정이 못 따라가다

의견 · 칼럼PostgreSQL 커미터 Robert Haas가 19 버전이 늦어지는 이유를 LLM에서 찾았습니다. 지난 10년간 9월 중순~10월 중순에 나오던 메이저 버전이 올해는 11월 이후로 밀립니다. 이전 버전 브랜치로 역이식된 커밋이 1년 새 74% 이상 늘었습니다. LLM이 버그를 쉽게 찾게 됐지만 고치는 일은 그만큼 쉬워지지 않았고, AI가 쓴 수정도 사람이 검토해야 하기 때문입니다.

그래서 무엇을 하나

AI 코드 리뷰나 버그 탐색을 돌리면 처리할 일이 한꺼번에 쏟아질 수 있습니다. Lobste.rs 댓글의 한 메인테이너처럼 결과를 3~5건씩 끊어 처리하는 방식을 정해 둡니다.

/loop · /schedule 사용법: 반복 확인 작업을 Claude에게 맡기기

Claude Code에는 반복 작업을 맡기는 방법이 세 가지 있습니다. /loop는 열린 세션 안에서 최소 1분 간격으로, Desktop 예약 작업은 내 컴퓨터에서, 클라우드 예약 작업(/schedule)은 노트북을 꺼도 Anthropic 클라우드에서 최소 1시간 간격으로 돕니다. 2.1.317에서 /loop 깨우기 누락이 고쳐졌고, /schedule은 요청하지 않은 커넥터가 붙으면 경고하게 됐습니다. 맡길 일의 성격에 맞춰 고르는 것이 핵심입니다.

설치 · 설정

  1. Claude Code를 2.1.317 이상으로 올린다.
  2. /schedule을 쓰려면 claude.ai 구독 계정(Pro, Max, Ultra, Team, Enterprise)으로 /login 한다.
  3. ANTHROPIC_API_KEY나 ANTHROPIC_AUTH_TOKEN이 설정돼 있으면 claude.ai 로그인보다 우선하므로 /schedule을 쓸 때는 끈다.
  4. 프로젝트 기본 루프 지시를 두려면 .claude/loop.md를, 모든 프로젝트 공통이면 ~/.claude/loop.md를 만든다.

실습

PR 관리 루프를 세션 안에서 돌리고, 매일 아침 요약을 클라우드 예약 작업으로 등록한다.

  1. /loop 5m check if the deployment finished and tell me what happened로 고정 간격 루프를 걸어 본다.
  2. what scheduled tasks do I have?로 작업 ID와 next run 시각을 확인한다.
  3. cancel the deploy check loop로 고정 간격 루프를 끈다. Esc로는 꺼지지 않는다.
  4. .claude/loop.md에 CI 실패 처리와 리뷰 코멘트 대응 지시를 몇 줄 적는다.
  5. 간격 없이 /loop만 입력해 Claude가 간격을 고르는 루프로 loop.md를 실행한다.
  6. 대기 중에 Esc를 눌러 루프를 멈추고 Pending wakeup cancelled가 뜨는지 본다.
  7. /schedule tomorrow at 9am, summarize yesterday's merged PRs로 일회성 클라우드 작업을 만든다.
  8. Claude가 묻는 저장소 · 프롬프트 질문에 답하고, 커넥터 경고가 뜨면 필요 없는 것을 뺀다.

바로 쓰는 프롬프트

세션 안에서 배포 · CI 짧게 감시

/loop 10m <배포 이름> 배포가 끝났는지 확인하고, 끝났으면 결과를 세 줄로 알려줘. 실패면 로그에서 원인 후보만 짚고 수정은 하지 마.

맨 /loop용 loop.md 만들기

이 저장소에 .claude/loop.md를 만들어줘. 맨 /loop를 실행하면 <브랜치 이름> PR의 CI가 빨간지 보고, 빨가면 실패 로그를 읽어 최소 수정안을 제안하고, 새 리뷰 코멘트가 있으면 하나씩 답하게 해줘. 푸시는 하지 말고 나에게 먼저 묻게 하고, 아무 일이 없으면 한 줄로만 보고하게 해줘.

노트북을 꺼도 도는 정기 요약

/schedule 평일 아침 9시 7분, <저장소 이름>에서 전날 머지된 PR과 새로 열린 이슈를 요약해줘. 커넥터는 <필요한 커넥터>만 남기고 나머지는 빼줘.

안 될 때

/schedule을 입력하면 Unknown command: /schedule이 나온다.
Console API 키나 ANTHROPIC_API_KEY · ANTHROPIC_AUTH_TOKEN이 claude.ai 로그인보다 우선하고 있을 수 있습니다. 이를 끄고 claude.ai 구독 계정으로 /login 합니다. 조직 소유자가 Scheduled tasks 토글을 껐다면 소유자에게 요청해야 합니다.
/loop 5m으로 건 루프가 Esc나 Ctrl+C로 멈추지 않는다.
고정 간격 루프는 키로 멈추지 않습니다. cancel the deploy check loop처럼 Claude에게 취소를 요청합니다.
반복 작업이 일주일쯤 뒤 사라졌다.
세션 범위 반복 작업은 만든 지 7일 뒤 마지막으로 한 번 돌고 지워집니다. 만료 전에 다시 만들거나 클라우드 · Desktop 예약 작업으로 옮깁니다.
클라우드 작업의 cron이 예상과 다른 시각에 돈다.
다섯 필드 cron만 쓰면 시각은 UTC로 해석됩니다. UTC로 바꿔 쓰거나 CRON_TZ= 접두어를 유지한 채 그 시간대로 씁니다. 정각에는 몇 분 늦게 시작할 수 있으니 9:07처럼 정각을 피합니다.

주의. 클라우드 예약 작업은 연결된 커넥터를 모두 기본 포함하고, 실행 중 쓰기도 할 수 있습니다. 실행은 기본으로 auto mode에서 시작해 분류 모델이 승인 여부를 판단합니다. 실행마다 구독 사용량이 차감되고, 계정당 예약 실행은 시간당 100회로 제한됩니다. 클라우드 작업은 로컬 파일에 접근하지 못하고 저장소를 새로 클론하며, 아직 research preview라 동작과 한도가 바뀔 수 있습니다.
