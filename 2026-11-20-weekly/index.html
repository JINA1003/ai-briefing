Anthropic, 역대 최대 기업공개로 나스닥에 상장했다

Claude를 만드는 Anthropic이 11월 18일 기업공개(회사 주식을 처음으로 일반 투자자에게 파는 일) 가격을 주당 83달러로 정했다. 클래스 A 주식 9억 8천만 주를 팔고, 11월 19일부터 나스닥에서 「ANT」라는 종목 코드로 거래를 시작했다. 공모 절차는 11월 20일에 마무리된다.

가격은 앞서 밝힌 희망 범위(70~78달러)보다 높게 정해졌고, 파는 주식도 계획보다 1억 5,500만 주 늘었다. 상장 분석 회사 Renaissance Capital은 이번 공모가 6월 SpaceX(750억 달러)의 기록을 넘어, 모은 돈 기준으로 역대 최대 기업공개라고 평가했다. 9억 8천만 주 가운데 약 9억 5,600만 주는 회사가 새로 파는 주식이다.

Renaissance Capital에 따르면 모은 돈은 813억 달러, 완전 희석 기준 시가총액은 1조 3,800억 달러다. 공모와 별도로 일부 투자자가 260억 달러어치를 사기로 했다. 9월 30일 기준 연 10만 달러 넘게 쓰는 고객이 1만 1,900곳을 넘고, 포춘 10대 기업 전부와 포춘 500 기업의 절반 이상이 들어 있다.

우리 팀에게는

알아 둘 흐름이다. 공모 발표에 Claude 요금제나 제품을 바꾼다는 내용은 없다. 우리가 매일 쓰는 도구를 만든 회사가 이제 상장사가 됐다는 점만 기억해 두면 된다.

Nvidia, CEO가 물러난 지 닷새 만에 매출이 두 배 뛴 실적을 냈다

Nvidia가 11월 17일 3분기(2027 회계연도, 10월 25일 마감) 실적을 냈다. 매출은 1,158억 달러로 1년 전보다 103% 늘었고, 그중 데이터센터 매출이 1,076억 달러(110% 증가)였다. 닷새 전인 11월 12일 Jensen Huang이 CEO와 이사직에서 즉시 물러났고, 이번 발표는 CFO Colette Kress가 임시 CEO로 맡았다.

Nvidia GPU는 Claude · GPT · Gemini 같은 모델을 학습하고 서비스하는 데이터센터의 핵심 부품이라, 이 회사 실적은 AI 투자가 이어지는지를 보는 지표로 읽힌다. 회사 발표는 사임 이유를 밝히지 않았다. CNBC에 따르면 이사회 의장 Harvey C. Jones는 실적 발표 통화에서 Huang이 회사 행동 규범에 맞지 않는 개인 행동을 스스로 알렸다고 했고, CEO로 복귀시킬 생각이 없다고 했다. 같은 발표에서 Nvidia는 Hugging Face(오픈소스 AI 모델을 올려 두는 플랫폼) 인수 합의와 차세대 시스템 Vera Rubin NVL72 출하 시작을 알렸다.

4분기 매출 전망은 1,300억 달러(±3%)이고, 중국 데이터센터 매출은 넣지 않았다. 매출은 시장 예상(LSEG 집계 1,091억 달러)을 넘었고 주가는 시간외 거래에서 4% 가까이 올랐다(CNBC). 다만 주가는 이달 들어 약 24% 빠지고 6주 연속 내린 상태였다. Kress는 앞으로의 투자 · 약정 · 보증을 엄격히 다시 보고 있다고 했다.

Anthropic, 제조 현장용 Claude 플러그인을 냈다

Anthropic이 11월 12일 제조업용 플러그인 「Claude for Manufacturing」을 냈다. 스킬 17개와 연결 4개(Autodesk Fusion · Infor · Microsoft 365 · Oracle NetSuite)로, 견적 작성 · 불량 보고서 · 공급사 견적 요청 · 아침 생산 보고를 회사가 이미 쓰는 시스템의 데이터로 초안까지 만든다. Team · Enterprise 요금제에서 Claude 플러그인 목록으로 설치한다.

제조 현장은 데이터가 ERP(전사 자원 관리 시스템) · CAD · 엑셀 내보내기에 흩어져 있어 사람이 옮겨 적는 일이 많다. 발표는 제조사 79%가 데이터를 손으로 입력한다는 2025년 Manufacturing Leadership Council 조사를 인용했다. 플러그인은 무언가를 바꾸거나 보내기 전에 멈추고 담당자 승인을 기다리며, 설비를 직접 움직이지 않는다. 연결이 없어도 정기 CSV 내보내기로 단일 작업 스킬 12개 중 11개가 돈다고 README가 적었다.

스킬 17개는 단일 작업 12개(고장 원인 진단 · 불량 보고서 · 근본 원인과 시정 조치 · 견적 작성 · 공급사 견적 비교 등)와 이들을 잇는 연쇄 5개다. README는 아침 생산 보고가 관리자의 60~90분을 아낀다고 적었다. Manufacturing Dive에 따르면 Infor CEO Kevin Samuelson은 Infor 고객에게 판도를 바꿀 일이라고 했고, Infor는 Infor 안에서 직접 변경까지 하는 자체 플러그인을 따로 냈다. 코드는 Anthropic 공식 플러그인 저장소(claude-plugins-official)에 공개됐고, README는 참조 구현이라 유지 보수와 기여 접수를 하지 않는다고 적었다.

우리 팀에게는

업종 전용 플러그인이 스킬 · 연결 · 승인 단계를 한 묶음으로 내는 형태가 공식으로 나왔다. → 팀에서 매주 반복하는 보고서 업무를 스킬로 만들 때, 공개된 스킬 폴더(단일 작업 + 연쇄, 변경 전 멈춤)를 설계 틀로 읽어 본다.

  • Team · Enterprise 요금제라면 Claude 플러그인 목록에서 Claude for Manufacturing을 찾아 설치한다.
  • 구성만 보려면 GitHub anthropics/claude-plugins-official 저장소의 plugins/claude-for-manufacturing/skills 폴더를 연다.

미국 큰 은행들, AI 에이전트가 낸 사고는 고객 책임이라고 못 박았다

외부 측정 · 보도미국 은행 Citi · PNC · Citizens가 이번 주 약관을 바꾸거나 고객에게 알렸다. 고객이 은행 로그인 정보를 외부 AI 도구에 주거나 계좌 접근을 허락하면, 그 도구가 한 일은 고객 책임이라는 내용이다. TechCrunch가 11월 18일 보도했다.

AI 에이전트가 지출 분석을 넘어 송금 · 공과금 납부까지 하게 되면서, 사고가 나면 누가 물어 주느냐가 문제가 됐다. Citi 약관은 도구가 로그인 정보를 흘리거나 해킹당해도 그 뒤 해커가 한 일은 고객 책임이고, 자동 도우미가 한 거래는 의도했든 아니든 은행이 되돌려 줄 책임이 없다고 적었다. 미국 1 · 2위 은행인 JPMorgan과 Bank of America는 10월에 비슷한 방침을 냈다.

Citi는 자기 은행이 제공하는 AI 에이전트는 추가 책임 걱정 없이 쓸 수 있다고 적었다. Citizens는 고객에게 보낸 메일에서 AI 도우미가 한 일은 모두 고객이 떠안는다고 알렸다. 기사는 대조 사례로, 11월 초 나온 Claude의 개인 금융 기능은 읽기 전용이라 돈을 옮기지 못한다고 소개했다.

우리 팀에게는

에이전트에 계정과 비밀번호를 넘기면 사고 책임도 함께 넘어온다는 원칙이 은행에서 먼저 굳어지고 있다. → 업무용 에이전트에도 사람 비밀번호를 주지 말고, 읽기 전용이나 범위가 좁은 전용 토큰부터 쓴다.

Knowledge Wiki (Anthropic 공식 예제, 문서 묶음을 위키로)

무엇인가

같은 문서 묶음에 질문이 반복되면, 에이전트는 질문마다 원문 검색을 처음부터 다시 하고 문서 사이에 걸친 사실은 놓친다. Knowledge Wiki는 Anthropic 공식 예제 모음 Claude Quickstarts의 하나로, 문서 묶음을 한 번 읽어 Claude Managed Agents(Anthropic 서버에서 도는 에이전트)의 메모리 저장소에 마크다운 위키로 정리한 뒤 질문은 위키로 답한다. 사실마다 출처가 붙고, 문서끼리 어긋나는 내용은 어긋난 채로, 바뀐 숫자는 이전 값과 함께 남는다. 예제 자료는 미국 SEC 공시로 만든 실제 M&A 실사 자료다.

왜 지금

11월 6일 위키를 동적 워크플로 하나로 짓는 방식으로 다시 만들어졌다. README 기준으로 위키를 읽는 작은 모델은 위키 없이 원문을 검색한 큰 모델과 1점 안쪽 차이로 답하고, 답 하나당 비용은 약 15분의 1이다. 위키는 한 번 짓는 데 약 19달러가 들고 질문 약 240개면 본전이다. Claude Quickstarts 저장소 별은 약 2.1만이다.

설치

claude "walk me through setting up the knowledge-wiki quickstart"

활용법

  1. 사내 규정 · 제품 문서처럼 자주 바뀌지 않는데 질문은 계속 들어오는 문서 묶음에 위키를 한 번 지어 둔다. 전에는 질문마다 원문 검색 비용이 들었고, 이제는 위키를 읽는 작은 모델로 답한다.
  2. 실사 · 감사 자료처럼 문서끼리 숫자가 다를 때, 위키가 충돌을 지우지 않고 문서별 값을 출처와 함께 남긴다. 어느 쪽이 최신인지 출처로 바로 확인한다.
  3. 코드를 돌리지 않고 노트북을 위에서 아래로 읽기만 해도 된다. 모든 셀에 실제 실행 결과가 들어 있어, 문서를 위키로 정리하는 에이전트 설계 사례로 읽힌다.
  4. 우리 문서로 바꿀 때는 노트북이 짓기 전에 정가 기준 예상 비용을 보여 주고 예산을 넘으면 멈춘다. 작은 묶음으로 먼저 시험한다.

예시 프롬프트

knowledge-wiki 예제를 <문서 폴더>에 맞게 바꾸고 싶어. 짓기 전에 예상 비용부터 보여 주고, quickstart 단계 크기로 먼저 시험해 줘.

주의. 먼저 git clone https://github.com/anthropics/claude-quickstarts로 저장소를 받고 cd managed-agents/knowledge-wiki에서 위 명령을 실행한다. Claude API 키(또는 ant auth login)가 필요하고 API 요금이 든다. 기록된 실행(core 단계, 공시 8건 · 2.8MB)은 23분 걸렸고 정가 약 16달러였다. SEC 자료를 받으려면 연락처를 담은 EDGAR_USER_AGENT를 넣어야 한다. 다른 단계 자료를 받기 전에 data_room/docs를 비운다.

champion-kit (Claude Code 공식 플러그인)

무엇인가

팀에 Claude Code를 들여오면 쓰는 사람만 쓰고, 같은 질문과 같은 지시가 사람마다 반복된다. champion-kit은 Anthropic이 공식 플러그인 마켓에 올린 플러그인으로, 팀에 Claude Code를 퍼뜨리는 담당자(챔피언)를 돕는다. 해커톤 · 오피스아워를 준비하고, 반복 질문을 FAQ로, 반복 지시를 CLAUDE.md 규칙 · 스킬 후보로 바꾸고, 팀의 AI 도입 단계를 근거와 함께 매긴 HTML 보고서를 쓴다.

왜 지금

11월 둘째 주 Anthropic 공식 플러그인 마켓(claude-plugins-official, 별 약 4.8만)에 새로 올라왔다. 명령은 hackathon · office-hours · patterns · climb · faq · maturity · routines 7개다.

설치

claude plugin install champion-kit@claude-plugins-official

활용법

  1. /champion-kit:patterns로 팀의 세션 기록에서 반복되는 지시를 찾는다. 전에는 사람마다 같은 지시를 매번 쳤고, 이제는 CLAUDE.md 규칙이나 스킬 후보로 한 번에 정리된다.
  2. /champion-kit:faq로 채팅방에 반복해 올라오던 질문을 팀이 찾아볼 답 한 편으로 묶는다.
  3. /champion-kit:hackathon으로 반나절 해커톤의 주제 · 진행표 · 준비물을 짠다. 백로그에서 Claude Code로 자동화할 만한 일을 주제로 고른다.
  4. /champion-kit:maturity로 팀 단위 도입 단계를 근거와 함께 매긴 ai-maturity-report.html을 만든다. 개인 순위는 매기지 않으니, 다음 분기 할 일을 정하는 자료로 쓴다.

예시 프롬프트

/champion-kit:hackathon 반나절 해커톤, 참가자 <인원>명, 주제는 우리 백로그에서 Claude Code로 자동화할 만한 일

주의. git 기록 · 이슈 · 세션 기록을 읽거나 파일을 쓰기 전에 승인을 묻는다. 다만 auto-accept · accept-edits 모드에서는 Claude Code가 파일 쓰기를 묻지 않으니, 매번 확인하려면 Manual 모드를 쓴다. /champion-kit:routines의 예약 작업은 연구 미리보기이고 사람 없이 돈다.

MinerU (문서를 AI가 읽는 마크다운으로)

무엇인가

스캔 PDF나 표가 많은 오피스 문서를 AI에게 통째로 주면 표가 깨지거나 긴 문서는 앞부분만 읽힌다. MinerU는 PDF · Office · 스캔 이미지를 LLM이 읽기 좋은 마크다운 · JSON으로 바꾸는 오픈소스 도구다. 저장소에 공식 mineru 스킬이 생겨, 에이전트가 문서를 페이지 · 블록 단위로 이어 읽고 답마다 위치표(doc:…/page:…/block:…)를 남긴다. 최신은 MinerU 4.2다.

왜 지금

이번 주 README에 공식 스킬과 설치 명령이 올라왔다. 전에는 커뮤니티 래퍼만 있었고, 그중 일부는 문서를 MinerU 호스팅 API로 보냈다. GitHub 별은 약 8.4만이다. 기본이 로컬 처리라 밖으로 보낼 수 없는 문서에도 쓸 수 있다.

설치

npx skills add opendatalab/MinerU --skill mineru --global --yes

활용법

  1. 스캔으로 받은 계약서 · 사양서를 물어볼 때, mineru 스킬로 먼저 마크다운으로 바꾸게 하면 표가 살아 있고 답마다 몇 쪽 어느 블록인지 위치가 붙는다. 전에는 답을 확인하려고 PDF를 다시 넘겼고, 이제는 위치표로 바로 찾아간다.
  2. 수백 쪽 보고서처럼 한 번에 안 읽히는 문서는 페이지 단위로 이어 읽게 한다. 뒷부분 내용이 빠진 답을 받지 않는다.
  3. 사내 문서를 검색용으로 쌓을 때 폴더째 마크다운으로 바꿔 둔다. 스킬 없이도 mineru-kit parse document.pdf -o document.md --tier standard로 바꾼다.

예시 프롬프트

mineru 스킬로 <파일 경로>를 마크다운으로 바꾸고, 표가 있는 페이지만 골라 요약해 줘. 요약 문장마다 위치표를 붙여 줘.

주의. 가벼운 문서는 basic 단계(RAM 2GB), 표 · 수식이 많으면 standard 이상(RAM 8GB)을 쓴다. 기본은 로컬 처리이고, --remote를 붙일 때만 문서가 원격 파싱으로 간다. 사내 문서에는 --remote를 쓰지 않는다. 텔레메트리가 처음에 켜져 있다(문서 내용 · 파일명은 빠진다고 한다). mineru telemetry disable 또는 MINERU_TELEMETRY_DISABLED=1로 끈다. 라이선스는 Apache 2.0에 조건을 더한 MinerU 자체 라이선스다.

Astryx (Meta 오픈소스 디자인 시스템)

무엇인가

AI에게 화면을 맡기면 매번 다른 버튼 · 여백 · 색이 나와 화면끼리 맞지 않는다. Astryx는 Meta가 공개한 React 19 · StyleX 기반 디자인 시스템(MIT, 베타)으로, 접근성을 갖춘 컴포넌트 150개 이상과 테마 7종 · 다크 모드, 문서 · 템플릿 · 코드 변환을 다루는 CLI를 담았다. 저장소에 AGENTS.md · CLAUDE.md · Claude 플러그인 폴더가 들어 있어, 사람과 AI가 같은 컴포넌트 규칙으로 화면을 짠다.

왜 지금

지난주 별이 13,660개 늘어 GitHub 트렌딩 맨 위에 올랐다(누적 약 3.1만). 처음부터 AI 에이전트가 쓸 것을 전제로 큰 회사가 낸 디자인 시스템이다.

설치

npm install @astryxdesign/core @astryxdesign/theme-neutral @stylexjs/stylex

활용법

  1. 사내 관리 화면을 Claude에게 맡길 때 Astryx 컴포넌트만 쓰게 하면, 화면마다 버튼 · 여백이 달라지지 않는다. 전에는 생성된 화면을 손으로 맞췄고, 이제는 정해진 부품 안에서만 조립된다.
  2. npm i -g @astryxdesign/cli로 CLI를 깔아 두면, 에이전트가 쓸 컴포넌트의 문서를 직접 찾아보고 짠다. 짐작한 속성 대신 문서에 있는 속성을 쓴다.
  3. 브랜드 색을 바꿀 때는 테마의 CSS 변수만 덮어쓴다. 컴포넌트 코드를 고치지 않는다.

예시 프롬프트

이 페이지를 Astryx 컴포넌트만으로 다시 짜 줘. 쓸 컴포넌트를 Astryx CLI 문서에서 먼저 찾아 목록으로 보여 줘.

주의. 아직 베타라 API가 바뀔 수 있다. React 19 이상과 StyleX가 필요하다.
