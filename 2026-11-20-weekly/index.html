Anthropic, 역대 최대 기업공개로 나스닥에 상장했다

Claude를 만드는 Anthropic이 11월 18일 기업공개(회사 주식을 처음으로 일반 투자자에게 파는 일) 가격을 주당 83달러로 정했다. 클래스 A 주식 9억 8천만 주를 팔고, 11월 19일부터 나스닥에서 「ANT」라는 종목 코드로 거래를 시작했다. 공모 절차는 11월 20일에 마무리된다.

가격은 앞서 밝힌 희망 범위(70~78달러)보다 높게 정해졌고, 파는 주식도 계획보다 1억 5,500만 주 늘었다. 상장 분석 회사 Renaissance Capital은 이번 공모가 6월 SpaceX(750억 달러)의 기록을 넘어, 모은 돈 기준으로 역대 최대 기업공개라고 평가했다. 9억 8천만 주 가운데 약 9억 5,600만 주는 회사가 새로 파는 주식이다.

Renaissance Capital에 따르면 모은 돈은 813억 달러, 완전 희석 기준 시가총액은 1조 3,800억 달러다. 공모와 별도로 일부 투자자가 260억 달러어치를 사기로 했다. 9월 30일 기준 연 10만 달러 넘게 쓰는 고객이 1만 1,900곳을 넘고, 포춘 10대 기업 전부와 포춘 500 기업의 절반 이상이 들어 있다.

우리 팀에게는

알아 둘 흐름이다. 공모 발표에 Claude 요금제나 제품을 바꾼다는 내용은 없다. 우리가 매일 쓰는 도구를 만든 회사가 이제 상장사가 됐다는 점만 기억해 두면 된다.

OpenAI와 Google, 같은 주에 새 모델을 내고 작업당 비용을 앞세웠다

OpenAI가 11월 17일 GPT-6.2 Astra와 Sol을 냈다. Astra는 어려운 전문 작업용, Sol은 일상 작업용이고, ChatGPT(Plus · Pro · Enterprise · Edu)와 Codex, API에서 쓴다. 하루 뒤 18일 Google은 Gemini 4 Neon을 냈다. 가장 어려운 장기 작업용 Carbon과 빠른 일상용 Hydrogen 사이에서 깊이와 효율을 맞춘 중간 모델이다.

두 회사 모두 점수보다 작업 하나에 드는 돈을 앞세웠다. OpenAI는 Astra의 API 값을 GPT-6 Astra보다 20% 낮췄다(100만 토큰당 입력 8달러, 출력 40달러). Google은 Neon이 기본 추론 설정에서 Carbon보다 작업당 비용이 32% 낮다고 밝혔다(입력 3달러, 출력 15달러, 컨텍스트 100만 토큰). OpenAI는 두 모델이 자체 위험 기준에서 사이버 보안 「Critical」 등급이라 보안 관련 도움을 더 막고, 이 때문에 일부 정당한 보안 연구도 제한된다고 했다.

외부 측정인 Artificial Analysis 지능 지수에서 Astra는 62점으로 Claude Fable 5.2(65점)에 이어 2위, Sol은 57점이었다(Decrypt). Neon은 Google 발표로 같은 지수에서 61점, 3위다. Ethan Mollick은 Astra가 「고르지 않고 이상하며」 다른 모델보다 다루기 어렵다고 평했고, Decrypt는 시험에서 모델이 빠진 파일이나 못 쓰는 도구를 알리지 않은 경우가 있었다고 전했다.

우리 팀에게는

Claude를 주로 쓰는 팀이라 당장 바꿀 일은 없다. 문서 요약 · 표 정리처럼 반복이 많은 작업을 API로 돌리고 있다면, 같은 작업을 Sol이나 Neon에 한 번 돌려 결과와 비용을 나란히 비교해 볼 만하다.

Anthropic, 제조 현장용 Claude 플러그인을 냈다

Anthropic이 11월 12일 제조업용 플러그인 「Claude for Manufacturing」을 냈다. 스킬 17개와 연결 4개(Autodesk Fusion · Infor · Microsoft 365 · Oracle NetSuite)로, 견적 작성 · 불량 보고서 · 공급사 견적 요청 · 아침 생산 보고를 회사가 이미 쓰는 시스템의 데이터로 초안까지 만든다. Team · Enterprise 요금제에서 Claude 플러그인 목록으로 설치한다.

제조 현장은 데이터가 ERP(전사 자원 관리 시스템) · CAD · 엑셀 내보내기에 흩어져 있어 사람이 옮겨 적는 일이 많다. 발표는 제조사 79%가 데이터를 손으로 입력한다는 2025년 Manufacturing Leadership Council 조사를 인용했다. 플러그인은 무언가를 바꾸거나 보내기 전에 멈추고 담당자 승인을 기다리며, 설비를 직접 움직이지 않는다. 연결이 없어도 정기 CSV 내보내기로 단일 작업 스킬 12개 중 11개가 돈다고 README가 적었다.

스킬 17개는 단일 작업 12개(고장 원인 진단 · 불량 보고서 · 근본 원인과 시정 조치 · 견적 작성 · 공급사 견적 비교 등)와 이들을 잇는 연쇄 5개다. README는 아침 생산 보고가 관리자의 60~90분을 아낀다고 적었다. Manufacturing Dive에 따르면 Infor CEO Kevin Samuelson은 Infor 고객에게 판도를 바꿀 일이라고 했고, Infor는 Infor 안에서 직접 변경까지 하는 자체 플러그인을 따로 냈다. 코드는 Anthropic 공식 플러그인 저장소(claude-plugins-official)에 공개됐고, README는 참조 구현이라 유지 보수와 기여 접수를 하지 않는다고 적었다.

우리 팀에게는

업종 전용 플러그인이 스킬 · 연결 · 승인 단계를 한 묶음으로 내는 형태가 공식으로 나왔다. → 팀에서 매주 반복하는 보고서 업무를 스킬로 만들 때, 공개된 스킬 폴더(단일 작업 + 연쇄, 변경 전 멈춤)를 설계 틀로 읽어 본다.

  • Team · Enterprise 요금제라면 Claude 플러그인 목록에서 Claude for Manufacturing을 찾아 설치한다.
  • 구성만 보려면 GitHub anthropics/claude-plugins-official 저장소의 plugins/claude-for-manufacturing/skills 폴더를 연다.

미국 큰 은행들, AI 에이전트가 낸 사고는 고객 책임이라고 못 박았다

외부 측정 · 보도미국 은행 Citi · PNC · Citizens가 이번 주 약관을 바꾸거나 고객에게 알렸다. 고객이 은행 로그인 정보를 외부 AI 도구에 주거나 계좌 접근을 허락하면, 그 도구가 한 일은 고객 책임이라는 내용이다. TechCrunch가 11월 18일 보도했다.

AI 에이전트가 지출 분석을 넘어 송금 · 공과금 납부까지 하게 되면서, 사고가 나면 누가 물어 주느냐가 문제가 됐다. Citi 약관은 도구가 로그인 정보를 흘리거나 해킹당해도 그 뒤 해커가 한 일은 고객 책임이고, 자동 도우미가 한 거래는 의도했든 아니든 은행이 되돌려 줄 책임이 없다고 적었다. 미국 1 · 2위 은행인 JPMorgan과 Bank of America는 10월에 비슷한 방침을 냈다.

Citi는 자기 은행이 제공하는 AI 에이전트는 추가 책임 걱정 없이 쓸 수 있다고 적었다. Citizens는 고객에게 보낸 메일에서 AI 도우미가 한 일은 모두 고객이 떠안는다고 알렸다. 기사는 대조 사례로, 11월 초 나온 Claude의 개인 금융 기능은 읽기 전용이라 돈을 옮기지 못한다고 소개했다.

우리 팀에게는

에이전트에 계정과 비밀번호를 넘기면 사고 책임도 함께 넘어온다는 원칙이 은행에서 먼저 굳어지고 있다. → 업무용 에이전트에도 사람 비밀번호를 주지 말고, 읽기 전용이나 범위가 좁은 전용 토큰부터 쓴다.

Claude Code 팀 「코드 90%를 Claude가 쓴다, 맡길 수 있는 건 검증 덕분」

Claude Code 팀이 11월 16일 블로그에 자기 팀의 검증 방식을 공개했다(글쓴이 Addy Osmani). 팀 코드의 약 90%를 Claude가 쓰고 검토한다고 밝히고, 그만큼 맡길 수 있는 이유로 검증 고리를 꼽았다. 검증 고리가 없으면 Claude를 한두 개밖에 동시에 못 돌린다는 것이다.

테스트는 장바구니 담기에서 결제까지처럼 사용자 흐름을 끝까지 따라가는 E2E 테스트를 먼저 고른다. 그다음이 속성 기반 테스트(입력을 많이 만들어 늘 지켜야 할 규칙을 확인), 차이 비교 테스트(옛 시스템과 새 시스템에 같은 입력을 넣어 결과 비교)다. 앱을 띄우고 조작하는 verify 스킬을 .claude/skills/에 두고 커밋 전에 쓰게 하며, 세 번 고쳐도 검사가 실패하면 Claude는 멈추고 사람을 부른다.

변경이 자기를 심사하는 규칙을 고칠 수 없도록, 리뷰 규칙(REVIEW.md)은 기준 브랜치에서 읽는다. 39개 항목의 안정성 점검표를 변경에 맞춰 보는데 보통 3~10개가 해당된다. 흔들리는 테스트는 건너뛰거나 재시도로 통과시키지 않고, 원인을 못 찾으면 이유를 적고 지운다.

우리 팀에게는

Claude에게 일을 더 맡기고 싶다면 프롬프트를 다듬기 전에 「끝났는지 확인하는 방법」부터 만든다. → 이번 주에 저장소 하나를 골라, 앱을 띄워 주요 흐름 하나를 확인하는 verify 스킬을 만들어 본다.

  • .claude/skills/verify/SKILL.md에 앱을 띄우고 주요 사용자 흐름 하나(예: 로그인 → 목록 → 저장)를 확인하는 절차를 적는다.
  • CLAUDE.md에 「커밋 전에 verify 스킬을 돌리고, 세 번 고쳐도 실패하면 멈추고 알려 달라」고 적는다.
  • PR을 열기 전에 테스트 · 빌드 · 린터처럼 싼 검사부터 돌리게 한다.
  • 새 검사 관문은 처음에는 관찰만 하다가, 믿을 만해지면 막도록 바꾼다.

MinerU (문서를 AI가 읽는 마크다운으로)

무엇인가

스캔 PDF나 표가 많은 오피스 문서를 AI에게 통째로 주면 표가 깨지거나 긴 문서는 앞부분만 읽힌다. MinerU는 PDF · Office · 스캔 이미지를 LLM이 읽기 좋은 마크다운 · JSON으로 바꾸는 오픈소스 도구다. 저장소에 공식 mineru 스킬이 생겨, 에이전트가 문서를 페이지 · 블록 단위로 이어 읽고 답마다 위치표(doc:…/page:…/block:…)를 남긴다. 최신은 MinerU 4.2다.

왜 지금

이번 주 README에 공식 스킬과 설치 명령이 올라왔다. 전에는 커뮤니티 래퍼만 있었고, 그중 일부는 문서를 MinerU 호스팅 API로 보냈다. GitHub 별은 약 8.4만이다. 기본이 로컬 처리라 밖으로 보낼 수 없는 문서에도 쓸 수 있다.

설치

npx skills add opendatalab/MinerU --skill mineru --global --yes

활용법

  1. 스캔으로 받은 계약서 · 사양서를 물어볼 때, mineru 스킬로 먼저 마크다운으로 바꾸게 하면 표가 살아 있고 답마다 몇 쪽 어느 블록인지 위치가 붙는다. 전에는 답을 확인하려고 PDF를 다시 넘겼고, 이제는 위치표로 바로 찾아간다.
  2. 수백 쪽 보고서처럼 한 번에 안 읽히는 문서는 페이지 단위로 이어 읽게 한다. 뒷부분 내용이 빠진 답을 받지 않는다.
  3. 사내 문서를 검색용으로 쌓을 때 폴더째 마크다운으로 바꿔 둔다. 스킬 없이도 mineru-kit parse document.pdf -o document.md --tier standard로 바꾼다.

예시 프롬프트

mineru 스킬로 <파일 경로>를 마크다운으로 바꾸고, 표가 있는 페이지만 골라 요약해 줘. 요약 문장마다 위치표를 붙여 줘.

주의. 가벼운 문서는 basic 단계(RAM 2GB), 표 · 수식이 많으면 standard 이상(RAM 8GB)을 쓴다. 기본은 로컬 처리이고, --remote를 붙일 때만 문서가 원격 파싱으로 간다. 사내 문서에는 --remote를 쓰지 않는다. 텔레메트리가 처음에 켜져 있다(문서 내용 · 파일명은 빠진다고 한다). mineru telemetry disable 또는 MINERU_TELEMETRY_DISABLED=1로 끈다. 라이선스는 Apache 2.0에 조건을 더한 MinerU 자체 라이선스다.

last30days (지난 30일 반응 조사)

무엇인가

새 도구나 주제를 두고 실제 사용자 반응을 알려면 Reddit · Hacker News · X를 탭마다 따로 뒤져야 했다. last30days는 주제 하나를 받아 Reddit · X · YouTube · Hacker News · Polymarket · GitHub 등을 한꺼번에 찾고, 지난 30일 반응이 큰 순으로 점수를 매겨 출처 링크가 달린 요약 한 장을 쓴다. Reddit · HN · Polymarket · GitHub은 설정 없이 되고, 나머지는 키나 로그인을 넣어야 열린다.

왜 지금

지난주 GitHub 트렌딩에서 별 2,423개가 늘었고(누적 약 7.1만), 지난 7일 중 3일 일간 트렌딩에 올랐다. 11월 16일 v4.3.0이 나왔다.

설치

/plugin marketplace add mvanhorn/last30days-skill

활용법

  1. 라이브러리나 SaaS 도입을 검토할 때 /last30days <도구 이름>을 돌리면, 실제 사용자 불만 · 칭찬과 출처 링크가 한 장으로 나온다. 전에는 검색 탭 여러 개를 오가며 모았고, 이제는 한 장을 읽고 원문은 필요한 것만 연다.
  2. 두 후보 중 하나를 고를 때는 /last30days <A> vs <B>로 비교를 묻는다. 회의 자료에 붙일 근거가 출처와 함께 남는다.
  3. 제품을 내놓은 뒤 반응을 볼 때 제품 이름으로 돌린다. 공식 채널 밖 커뮤니티 반응을 놓치지 않는다.
  4. 같은 주제를 매달 추적하려면 LAST30DAYS_STORE=1을 켜 결과를 로컬 SQLite에 쌓는다. 지난달과 이번 달 반응을 나란히 본다.

예시 프롬프트

/last30days Claude Code plugins people actually use

주의. 마켓을 추가한 뒤 /plugin install last30days로 설치를 마친다. X 공식 API는 최근 약 1주 글만 돌려준다. 재정렬용 키(OpenAI · xAI 등)를 넣으면 주제와 본문 조각이 그 업체로 가고, 키가 없으면 외부 호출 없이 로컬 점수 모델을 쓴다. ScrapeCreators는 1만 회 무료 뒤 종량제, Brave Search는 월 2,000회 무료다. 마켓 플러그인과 npx skills 설치를 함께 하면 /last30days가 두 개 뜬다.

Yogurt (내 컴퓨터 안에서만 도는 AI 회의록)

무엇인가

AI 회의록을 쓰려면 보통 회의에 봇이 들어오거나 녹음이 외부 서버로 간다. Yogurt는 받아쓰기와 요약을 모두 내 컴퓨터에서 하는 무료 오픈소스 회의록 앱이다(MIT, Granola 대안). Zoom · Teams · Meet 통화를 알아채 녹음을 제안하고, 마이크와 시스템 소리를 녹음해 봇 없이 기록한다. 받아쓰기는 whisper.cpp, 요약과 질문 답변은 llama.cpp로 돌리는 Gemma 4 · gpt-oss · Qwen3 계열 로컬 모델이 맡는다.

왜 지금

11월 셋째 주 스킬 순위에 새로 들어왔다. GitHub 별은 약 2,600개다. 계정 없이 쓰고, 처음 설정 때 모델을 내려받은 뒤에는 인터넷 없이 돈다.

설치

brew install --cask frigadehq/yogurt/yogurt

활용법

  1. 매주 하는 팀 회의에, 통화가 시작될 때 녹음을 켜 두면 끝난 뒤 요약이 남는다. 전에는 한 사람이 받아 적느라 회의에 덜 참여했고, 이제는 모두 대화에 집중한다.
  2. 외부 협력사 회의처럼 녹음을 클라우드 서비스에 올리기 곤란한 자리에 쓴다. 회의 데이터는 내 컴퓨터에만 남는다(인터넷은 모델 내려받기와 업데이트 확인에만 쓴다).
  3. 「지난주 회의에서 배포 날짜를 뭐라고 했지?」처럼 지난 회의를 물어보면, 녹음을 다시 듣지 않고 답을 받는다.
  4. 설정 → AI apps에서 로컬 MCP 서버를 켜면 Claude 같은 앱이 회의록 · 받아쓰기를 읽기 전용으로 읽는다. 회의 내용으로 할 일 목록이나 이슈 초안을 바로 만든다.

예시 프롬프트

Yogurt MCP로 이번 주 회의 받아쓰기를 읽고, 내가 맡은 할 일만 마감 순으로 정리해 줘. 항목마다 어느 회의, 몇 시쯤 나온 말인지 함께 적어 줘.

주의. 봇이 들어오지 않으니 상대에게 녹음한다는 사실을 직접 알려야 한다고 FAQ가 적었다. Mac은 Apple silicon과 macOS 14.4 이상, 메모리 8GB가 필요하다. 오디오는 기본으로 저장되며 설정에서 끌 수 있다. MCP 서버를 켜 두면 내 계정으로 도는 앱은 따로 토큰 없이 회의 기록(참석자 이름 · 이메일 포함)을 읽을 수 있고, 연결한 앱이 읽은 내용을 자기 온라인 모델로 보낼 수 있다.

ffmpeg-skill (에이전트용 로컬 영상 편집)

무엇인가

영상 한 토막을 자르고 세로로 바꿔 내보내려면 편집 프로그램을 열거나 FFmpeg 옵션을 찾아야 했다. ffmpeg-skill은 FFmpeg · ffprobe 위에 도구 42개를 얹은 스킬이자 MCP 서버로, 자르기 · 이어 붙이기 · 무음 제거 · 자막 · 음량 맞추기 · 쇼츠 · 릴스 · 유튜브 규격 내보내기를 Claude Code가 대신 돌린다. 클라우드와 API 키 없이 내 컴퓨터에서 돌고, 자막용 음성 인식도 로컬 엔진을 쓴다.

왜 지금

지난주 GitHub 트렌딩에서 별 2,894개가 늘었고(누적 약 8,500), 지난 7일 중 2일 일간 트렌딩에 올랐다. 11월 19일 v3.15.0에서 새 컴퓨터를 한 번에 준비하는 npx ffmpeg-skill setup이 생겼다.

설치

npx ffmpeg-skill setup

활용법

  1. 회의 · 세미나 녹화에서 쓸 구간만 공유할 때, 시간대와 목적만 말하면 영상 확인 → 자르기 → 비율 맞추기 → 내보내기 → 규격 검사까지 돈다. 전에는 편집 프로그램에서 구간을 찾아 다시 내보냈고, 이제는 한 문장으로 끝난다.
  2. 발표 영상에 자막을 붙일 때 로컬 음성 인식으로 자막 파일을 만들어 영상에 입힌다. 녹음이 외부 서비스로 나가지 않는다.
  3. 말 사이 공백이 긴 녹화는 무음 제거로 길이를 줄이고, 음량을 플랫폼 기준에 맞춘다.
  4. 폴더 하나의 영상을 같은 규격으로 일괄 변환한다. 원본과 같은 이름으로는 저장하지 않아 원본이 덮이지 않는다.

예시 프롬프트

`interview.mp4`에서 0:45~1:20과 5:00~5:25만 남겨서 60초 릴스로 만들어 줘. 내보낸 뒤 릴스 규격 검사까지 해 줘.

주의. 설치 뒤 npx ffmpeg-skill doctor로 도구별 준비 상태를 보고, 자막이 필요하면 pip install faster-whisper를 깐다. setup은 FFmpeg가 없으면 패키지 관리자로 설치한다(macOS는 brew install ffmpeg-full). 건너뛰려면 --no-ffmpeg를 붙인다. Python 3.10 이상, Node 16 이상이 필요하다. 1시간짜리 1080p 재인코딩은 기본 제한 1800초에 걸려 --timeout이나 --fast가 필요하다고 README가 적었다. 얼굴 · 피사체 인식이 없어 세로 변환은 기본으로 가운데를 자른다.
