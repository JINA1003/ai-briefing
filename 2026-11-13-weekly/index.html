Anthropic 최상위 모델 Fable 새 판 출시, 코딩 시험에서 Opus를 앞섰다

Anthropic이 11월 9일 최상위 모델 Claude Fable 5.2와 Mythos 5.2를 내놓았다. 둘은 같은 모델이다. Fable은 사이버 공격 · 생물 연구 관련 안전장치를 더해 누구에게나 열고, Mythos는 심사를 통과한 보안 · 생명과학 조직에만 연다.

에이전트 코딩 시험 FrontierSWE v2에서 Fable 5.2는 69.9%로 Opus 5.5(62.3%)와 GPT-6 Astra(65.5%)를 앞섰다. Anthropic은 Fable 5.2 에이전트 약 1,000개가 페르마의 마지막 정리 증명을 Lean(수학 증명을 컴퓨터로 검증하는 언어)으로 30시간 만에 옮겼다고 밝혔다. 같은 설정에서 Opus 5.5는 18시간 동안 26%에 그쳤다. 그래도 Anthropic은 대부분의 코딩은 Opus 5.5로 시작하고, 가장 어렵고 답이 열린 일에만 Fable로 올리라고 권한다.

API 가격은 100만 토큰당 입력 8달러, 출력 40달러이고 빠른 모드는 16달러 · 80달러다. 고위험 보안 요청을 안전 분류기가 막으면 Opus 4.8이 대신 답하며, 이런 차단은 5.1보다 약 55% 줄었다고 한다. 외부 평가사 Artificial Analysis는 지능 지수 65로 74개 모델 중 1위로 매겼지만, 과제당 26.54달러 · 44.1분으로 가장 비싸고 느린 축이라고 평가했다.

우리 팀에게는

평소에는 Opus 5.5를 그대로 두고, 오래 안 풀리는 버그나 큰 설계처럼 어려운 일에만 Fable로 바꿔 결과와 사용량을 비교해 보자. Pro와 Team 표준 좌석은 주간 한도의 최대 50%까지 Fable에 쓸 수 있다.

  • claude update로 Claude Code를 2.1.321 이상으로 올린다.
  • /model에서 Fable을 고른다.
  • 같은 과제를 Opus 5.5와 Fable 5.2로 한 번씩 돌리고, 결과와 /usage 사용량을 비교한다.

Google, 큰 모델 Carbon을 모두에게 열고 이틀 뒤 빠른 모델 Hydrogen을 냈다

Google이 11월 10일 최상위 모델 Gemini 4 Carbon을 개발자와 기업에 열었고, 12일에는 빠른 실행용 Gemini 4 Hydrogen을 냈다. Carbon은 2주 전까지 사이버 보안 방어자에게만 열려 있었다. Hydrogen은 깊은 추론은 Carbon에 맡기고 에이전트의 일상 작업을 빨리 처리하는 모델이다.

큰 모델과 빠른 모델을 섞어 쓰는 방식이 도구 안으로 들어왔다는 점이 핵심이다. Google의 코딩 도구 Antigravity에는 한 세션 안에서 Carbon과 Hydrogen을 번갈아 쓰는 Orchestrator가 붙었고, Google은 Carbon에 가까운 성공률을 내면서 할당량은 평균 24% 덜 쓰고 19% 빨리 끝냈다고 밝혔다. 같은 주 Anthropic도 Fable을 작은 모델에게 일을 나눠 주는 지휘자로 쓸 수 있다고 소개했다.

Carbon은 100만 토큰당 입력 2달러 · 출력 10달러의 도입가로 시작해 11월 30일 이후 4달러 · 20달러가 된다. Hydrogen은 입력 1.50달러 · 출력 7.50달러이고, Terminal-Bench 4.1에서 57%(이전 3.8 Flash 18.2%)에 작업을 2.5배 빨리 끝낸다고 한다. Carbon의 공격 시험 침투율은 3.1%에서 0.8%로 낮아졌지만, 외부 문서에 숨긴 지시(프롬프트 인젝션) 방어는 아직 개선할 영역이라고 Google 스스로 적었다. 수치는 모두 Google 발표다.

우리 팀에게는

Claude로 어려웠던 코딩 · 조사 과제가 있으면 11월 30일 도입가가 끝나기 전에 Carbon과 나란히 돌려 비교해 볼 만하다. 웹 페이지나 외부 문서를 읽히는 에이전트에 붙일 때는 프롬프트 인젝션 한계를 감안한다.

  • Google AI Studio에서 Gemini 4 Carbon과 Hydrogen을 고르고, 지금 Claude에 맡기는 작업 하나를 같은 입력으로 돌려 본다.
  • Hydrogen은 생각 수준을 기본 high와 xhigh로 바꿔 가며 속도와 답의 질을 비교한다.
  • Claude Code에서도 서브에이전트마다 모델을 나눠, 계획은 큰 모델 · 반복 실행은 작은 모델에 맡기는 같은 분업을 시험해 본다.

AWS, 에이전트가 만든 「내 PC 속 AWS」를 무료로 공개했다

AWS가 11월 11일 계정 없이 내 PC에서 AWS API를 흉내 내는 aws-emulator를 공개했다. 오프라인으로 무료로 돌고, 공개 API 모델 400여 개로 서비스 200여 개를 다룬다. 라이선스는 누구나 제한 없이 쓰는 CC0다.

화제가 된 건 만든 방식이다. 에이전트가 실제 AWS에서 통과하는 시험을 먼저 쓰고, 에뮬레이터가 같은 시험을 통과할 때까지 고쳤다. 모든 변경은 보안 에이전트 여럿의 공격적 리뷰와 코드 리뷰, 손대면 안 되는 코드를 막는 검사를 거쳐야 합쳐진다. 글을 쓴 Swami Sivasubramanian은 엔지니어의 일이 코드를 쓰는 것에서, 언제 맞는지를 정하는 명세 · 시험 · 합치기 관문을 만드는 것으로 옮겨 간다고 정리했다.

그는 에이전트로 예전 시스템을 다시 만들 때 결과를 확인할 수단이 없어 나흘 밤을 감독했는데, 명세와 시험 환경을 주자 두 시간 만에 끝났다고 썼다. Simon Willison은 첫 3주 커밋이 29,684개였다고 전했다. 실제 AWS와 다르게 동작하는 부분은 저장소의 things-that-do-not-work 폴더에 모아 두었다.

우리 팀에게는

AWS를 쓰면 클라우드 비용 없이 에이전트가 고친 코드를 바로 돌려 볼 수 있다. AWS를 안 써도 교훈은 같다. Claude에게 일을 맡기기 전에 결과를 확인할 테스트 · 실행 명령부터 알려 주자.

  • AWS CLI 2.35.0 이상에서 에이전트용 스킬로 설치한다: aws agent-toolkit add-skill --skill-name aws-emulator --region us-east-1
  • macOS에서는 짧은 Dockerfile로 만든 컨테이너 안에서 돌리므로 Docker가 필요하다.
  • 저장소 issues/things-that-do-not-work 폴더에서 실제 AWS와 다른 부분을 먼저 확인한다.
  • 개발 · 테스트용이다. 운영이나 보안 테스트에는 쓰지 않는다.

AI에 파일 · git을 열어 주는 공식 연결 서버, 보안 구멍 10개를 막았다

MCP(AI가 외부 도구 · 데이터에 붙는 표준 연결 방식)의 공식 서버 묶음이 11월 11일 v2.4.0에서 filesystem · git · fetch 서버의 취약점 6개를 고쳤다. 다음 날 12일에는 MCP 서버를 시험하는 공식 도구 MCP Inspector가 2.15.0에서 취약점 4개를 고쳤다.

git 서버는 남의 저장소를 읽기만 해도 그 저장소 .git/config에 적힌 프로그램이 서버 권한으로 실행될 수 있었다. filesystem 서버는 검사하는 순간 폴더를 심볼릭 링크로 바꿔치기하면 허용 폴더 밖 파일을 읽을 수 있었다. Inspector는 클라우드 메타데이터 주소를 막지 못했고, 남이 준 server.json이 NODE_OPTIONS 같은 위험한 환경 변수를 미리 보기에서 숨길 수 있었다.

고친 버전은 filesystem 2.3.0, git · fetch 2026.11.11, Inspector 2.15.0이다. filesystem을 날짜 버전(2025.1.14~2026.8.31)으로 쓰던 사람은 패키지 관리자가 2.3.0을 업그레이드로 보여 주지 않아 직접 지정해야 한다. git 서버는 이제 Git 2.31 미만에서는 실행을 거부한다.

우리 팀에게는

Claude Code에 이 서버들을 붙여 쓰거나 Inspector로 남의 서버를 열어 본 적이 있다면 오늘 올리자. 특히 남의 저장소를 git 서버로 읽게 하는 경우가 위험했다.

  • claude mcp list로 연결된 MCP 서버와 패키지 이름을 확인한다.
  • filesystem은 npm install @modelcontextprotocol/server-filesystem@2.3.0으로 버전을 직접 지정한다.
  • mcp-server-git · mcp-server-fetch는 2026.11.11 이상으로 올리고, git --version으로 Git이 2.31 이상인지 먼저 본다.
  • Inspector는 npx @modelcontextprotocol/inspector@latest로 최신판을 받는다.

데이터를 안 남긴다던 AI 업체가 뚫려, Notion AI 대화 일부가 노출됐을 수 있다

Notion이 AI 처리를 맡기던 업체 Fireworks AI의 보안 사고로 Notion AI 채팅 기록 일부가 노출됐을 수 있다고 공지했다. 영향은 워크스페이스 1% 미만이고, 대부분의 기록에는 워크스페이스 · 사용자 · 회사와 이어지는 정보가 없다. The Register는 11월 10일 Fireworks가 10월에만 두 번 공격당했다고 보도했다.

Fireworks는 계약상 데이터를 남기지 않기로 했지만, Notion 조사에서 쓰던 엔드포인트에 데이터가 남아 있던 것으로 드러났다. 우리가 쓰는 AI 기능 뒤에는 보이지 않는 모델 업체가 있고, 「저장 안 함」 약속도 사고가 나면 확인이 필요하다는 사례다. Notion은 Fireworks 연결을 끊고 데이터를 지웠으며, 관련 기능 Insights를 멈추고 주요 업체의 데이터 보존 감사를 시작했다.

Fireworks의 첫 사고(10월 6일 감지)에서는 일부 고객의 API 키와 토큰이 든 환경 변수가 노출됐다. 두 번째는 10월 23일 연구용 기기를 맡긴 클라우드 업체가 뚫리며 결제 정보와 일부 모델 가중치 · 데이터셋에 접근이 있었다. Bloomberg는 Fireworks가 Cursor · Harvey와도 영향을 확인 중이라고 보도했지만, 두 회사가 실제로 영향을 받았는지는 확인되지 않았다.

우리 팀에게는

AI 채팅에 비밀번호 · API 키 · 고객 정보를 붙여 넣지 말자. 붙여 넣은 적이 있다면 Notion 권고대로 바로 교체하고, 우리가 쓰는 AI 도구가 어느 모델 업체로 데이터를 보내는지 한 번 확인해 두자.

  • Notion 워크스페이스 소유자는 데스크톱 브라우저에서 사이드바 ? → Security incident review로 영향 여부를 확인한다.
  • Notion에서 따로 연락이 없었다면 영향 대상이 아니다.
  • AI 채팅에 넣었던 비밀번호 · API 키가 떠오르면 바로 교체한다.

Claude에 팀이 함께 쓰는 화이트보드와 시트가 생겼다

Anthropic이 11월 10일 Claude Whiteboards와 Sheets를 베타로 내고, 10월 베타였던 Dashboards를 Claude Data라는 이름으로 정식 출시했다. 셋 다 모든 유료 플랜의 웹 · 데스크톱 · 모바일에서 쓴다.

전에는 Claude가 준 답을 사람이 Miro나 엑셀로 옮겼다. 이제는 Claude 안에서 팀이 함께 만든다. Whiteboards는 말로 한 계획을 담당자 · 날짜가 붙은 보드로 바꾸고, 메모를 주제별로 묶어 할 일 초안을 쓴다. 완성한 보드는 문서 · 슬라이드로 바꾸거나 Lucid · Miro로 옮긴다. Sheets는 탭 · 수식 · 서식 · 드롭다운이 있는 시트를 만들고, Claude가 고친 칸을 표시해 변경을 따라가게 한다.

Claude Data는 Redshift · BigQuery · ClickHouse 같은 데이터 창고에 질문해 대시보드를 만들고, 공유받은 사람은 주인이 승인한 쿼리 결과만 본다. Team 플랜은 셋 다 기본으로 켜져 있다. Enterprise는 Whiteboards · Sheets가 기본으로 꺼져 있고, Claude Data는 11월 19일부터 기본으로 켜진다. Sheets는 아직 기능이 단순하다고 Anthropic이 밝혔다.

우리 팀에게는

다음 회고나 회의 메모 하나를 Whiteboards에 넣어 담당자 · 날짜가 붙은 타임라인으로 바꿔 보자. 복잡한 계산이 필요한 표는 아직 .xlsx나 CSV로 내보내 다룬다.

  • 관리자는 Organization settings > Artifacts에서 세 도구가 켜져 있는지 확인한다.

7

improve (shadcn)

무엇인가

코드베이스에 고칠 곳이 많다는 건 알아도, 무엇부터 어떻게 고칠지 정리하는 데 시간이 더 든다. improve는 가장 좋은 모델로 코드를 감사해 문제마다 근거 위치 · 영향 · 품 · 확신도를 매기고, 고칠 일마다 더 싼 모델이 그대로 따라 할 수 있는 계획서를 plans/ 폴더에 마크다운으로 쓴다. 이름 그대로 개선할 거리를 찾아 계획만 만들고, 소스 코드는 직접 고치지 않는다.

왜 지금

11월 둘째 주 GitHub 별 증가 순위 6위(+361)로 올라왔다. 이 순위의 집계 출처는 확인하지 못했다. README 기준 별은 1.15만 개이고 MIT다. 같은 주 Anthropic과 Google이 함께 내세운 「비싼 모델은 계획, 싼 모델은 실행」 분업을 스킬 하나로 바로 해 볼 수 있다.

설치

npx skills add shadcn/improve

활용법

  1. 며칠 걸릴 리팩터링을 앞두고 /improve로 전체 감사를 돌리면, 어디부터 손댈지 회의로 정하던 일이 파일 · 줄 근거가 붙은 문제 표와 우선순위 · 의존 순서가 적힌 계획 목록으로 바뀐다.
  2. PR을 올리기 전에 /improve branch로 지금 브랜치가 바꾼 것만 감사하면, 리뷰어가 짚을 문제를 먼저 잡고 고칠 계획까지 손에 쥐고 리뷰에 들어간다.
  3. 보안이 걱정되는 저장소에 /improve security를 돌리면 비밀값은 내용 없이 위치와 종류만 적고 교체를 권하므로, 점검 결과를 팀 채널에 그대로 공유해도 키가 새지 않는다.
  4. --issues를 붙이면 계획이 GitHub 이슈로 올라가 칸반 보드에 카드를 붙이듯 바로 나눠 맡길 수 있다. 직접 맡길 때는 /improve execute <계획 파일>이 싼 모델을 일회용 worktree에서 돌리고 결과를 검토하며, 합치는 결정은 사람이 한다.

예시 프롬프트

/improve branch 이번 브랜치에서 바뀐 코드만 봐 줘. 버그와 성능 문제를 우선으로 하고, 계획마다 확인 명령과 완료 기준을 넣어 plans/에 써 줘.

주의. 분석은 읽기 전용이고 쓰는 곳은 plans/뿐이라고 README가 밝힌다. 하위 에이전트가 문제를 과하게 보고하는 경향이 있어 인용 위치를 다시 확인한다고 적었지만, 계획은 실행 전에 사람이 읽고 검토하는 것이 전제다.

8

modern-web-guidance (GoogleChrome)

무엇인가

코딩 에이전트는 학습 때 본 낡은 웹 코드를 그대로 짠다. 모달 하나에도 브라우저에 이미 있는 기능 대신 자바스크립트 라이브러리를 끌어온다. modern-web-guidance는 최신 웹 플랫폼 모범 사례와 브라우저 호환성 데이터를 스킬로 넣어, 에이전트가 작업 중에 관련 가이드를 찾아 읽고 브라우저 기본 기능으로 짜게 한다. Google Chrome · Microsoft Edge · Mozilla Firefox · MDN 팀이 함께 관리하고, 검색은 내 컴퓨터에서 돌아 API 키가 필요 없다.

왜 지금

11월 10일 Show HN에 「코딩 에이전트를 2019년식 자바스크립트에서 꺼내기」로 올라와 209점을 받았다. 브라우저 회사 세 곳과 MDN이 같이 낸 드문 공동 작업이고, 별은 약 7,200개, 라이선스는 Apache-2.0이다. Claude Code · Codex · Gemini 등 여러 에이전트용으로 함께 설치된다.

설치

npx modern-web-guidance@latest install

활용법

  1. 오래된 프론트엔드 프로젝트를 정리할 때 npx modern-web-guidance@latest legacy-scan .을 먼저 돌리면, 리팩터링 범위를 감으로 정하던 것이 바꿀 만한 낡은 패턴 목록으로 바뀐다.
  2. 라이브러리 도입을 검토할 때, 예를 들어 「모달을 열 때 배경을 흐리게 애니메이션」을 시키면 전에는 에이전트가 라이브러리를 끌어왔다. 이제는 search로 가이드를 찾고 retrieve로 읽은 뒤 브라우저 기본 기능으로 짜서 의존성이 하나 줄고 코드가 짧아진다.
  3. 다크 모드 · 글자 크기 · 색 대비 · 스크롤바 같은 흔한 화면 작업에서 가이드에 적힌 함정과 대체 방법, 브라우저 지원 범위까지 따르게 해, 특정 브라우저에서만 깨지는 일을 줄인다.
  4. 나온 지 석 달이 안 된 기능과 실험 API는 기본으로 막혀 있다. 팀이 쓰기로 합의했다면 프로젝트 루트의 .mwgrc에 켜 두고 커밋해, 모든 팀원의 에이전트가 같은 기준으로 짜게 한다.

예시 프롬프트

modern-web-guidance 스킬로 <src/components> 폴더에서 최신 웹 표준으로 바꿀 수 있는 낡은 패턴을 찾아 줘. 항목마다 근거가 된 가이드 ID와 브라우저 지원 범위를 적고, 바꿀지 말지는 내가 고를게.

주의. 설치 수, 호출한 에이전트 이름, 조회한 가이드 ID, 에이전트가 만든 검색어를 익명으로 수집한다. 원래 프롬프트는 모으지 않는다고 적혀 있다. 끄려면 셸 설정(.zshrc 등)에 DISABLE_TELEMETRY=1을 둔다.

T3 Code

무엇인가

긴 작업을 에이전트에게 걸어 두고 자리를 뜨면, 결과를 보고 다음 지시를 하려고 PC 앞으로 돌아와야 한다. T3 Code는 내 컴퓨터에 깔린 Claude Code · Codex · Cursor · OpenCode 같은 코딩 에이전트를 데스크톱 앱, 브라우저, 휴대폰 앱(iOS · Android) 한 화면에서 부리는 오픈소스(MIT)다. 에이전트를 대신하지 않고, PC에서 도는 t3 서버가 이미 로그인된 에이전트와 기존 구독을 그대로 쓴다.

왜 지금

11월 둘째 주 스킬 순위 1위(주간 별 +17.1k)로 올라왔다. 이 순위의 집계 출처와 별 증가 수는 확인하지 못했다. 저장소 별은 약 5.83만 개다.

설치

npx t3@latest

활용법

  1. 점심 전에 테스트 보강 같은 긴 작업을 맡겨 두면, 전에는 돌아와서야 중간에 멈춘 걸 알았다. 이제는 휴대폰 앱에서 진행 상황을 보고 막힌 곳에 바로 다음 지시를 보낸다. 집 밖에서 앱으로 로봇청소기를 돌리는 것과 같다.
  2. 회의실에 노트북 없이 들어갔을 때도 브라우저(app.t3.codes)로 내 PC의 세션을 열어, 방금 나온 질문을 에이전트에게 바로 확인시킨다.
  3. Claude Code와 Codex를 함께 쓰는 사람은 터미널 탭을 오가던 일을 한 화면으로 모아, 같은 과제를 두 에이전트에 맡기고 결과를 나란히 본다.
  4. 다른 기기에서 붙는 방법은 같은 네트워크, Tailscale, T3 Connect 세 가지다. 저장소의 docs/user/remote-access.md를 따라 고른다.

예시 프롬프트

https://github.com/pingdotgg/t3code 의 docs/user/remote-access.md를 읽고, 내 Mac에서 띄운 t3 서버에 휴대폰으로 안전하게 붙는 방법을 단계별로 정리해 줘. 외부에 포트를 여는 단계가 있으면 따로 표시하고, 실행은 하지 마.

주의. 에이전트 하나 이상을 먼저 설치하고 로그인해 둬야 쓸 수 있다(예: claude auth login). 원격 접속은 밖에서 내 PC의 에이전트를 부리는 일이므로 접속 경로를 먼저 정한다. 설치 스크립트를 셸에 바로 넘기는 방법은 내용을 읽고 쓴다. 메인테이너의 리뷰 여력이 적다고 README가 밝힌다.

클로드를 2024년처럼 쓰지 마라: Anthropic 엔지니어링 리드의 네 가지 습관

녹화 당시 Anthropic에서 Claude.ai · Cowork · Claude Code 데스크톱 엔지니어링을 이끈 Felix Rieseberg가 Silicon Valley Girl 팟캐스트(10월 20일, 53분)에서 한 말을 추렸다. 요지는 사람들이 AI에 너무 적게 요구한다는 것이다. 모델은 빠르게 좋아지는데 쓰는 습관은 그대로라, 예전 방식이 오히려 결과를 깎는다. 아래 네 가지는 오늘 바로 바꿀 수 있다.

설치 · 설정

  1. 결과를 맡긴다. 전에는 크래시 하나, 이메일 하나씩 잘게 쪼개 넘겼다. 이제는 크래시 데이터 전부와 목표를 주고, 무엇을 고칠지 Claude가 정하게 한다. 미리 잘라 준 데이터보다 문서가 잘 된 도구를 쥐여 주라고 했다.
  2. 역할극 대신 도구를 묻는다. 전에는 「넌 뛰어난 엔지니어야」로 시작했다. 이제는 「이 분야 최고 전문가라면 어떤 도구를 쓸지 말하고, 그걸 써」라고 한다. 3D · 모션 작업에 Blender를 쓰게 하자 나아졌다는 예를 들었다.
  3. 예전 스킬은 꺼 두고 비교한다. 「좋은 스킬의 반감기는 아주 짧다」고 했다. 스킬을 빼면 결과가 더 나을 때도 있으니, 켠 것과 끈 것을 같은 일로 비교한다.
  4. 검사는 다른 세션에 맡긴다. 방금 일한 세션이 스스로를 평가하게 하지 않는다. 별도 스레드 여러 개가 결과가 틀렸음을 증명하려 하고, 판정 세션이 어떤 지적이 맞는지 가린다. 1차 출처와 대조하는 단순 사실 확인은 에이전트 하나에 맡겨도 된다고 했다.

실습

지금 하던 일 하나를 「결과 맡기기 + 다른 세션 검사」로 다시 해 본다.

  1. 최근 Claude에게 잘게 쪼개서 시킨 일 하나를 고른다.
  2. 아래 첫 번째 프롬프트로 바라는 결과와 자료 전체를 한 번에 맡긴다.
  3. 결과가 나오면 새 세션을 열고 세 번째 프롬프트로 결과를 반박하게 한다.
  4. 자주 쓰는 스킬 하나를 꺼 두고 같은 일을 다시 시켜, 켰을 때와 결과를 비교한다.

바로 쓰는 프롬프트

결과를 통째로 맡길 때

<바라는 결과>를 원해. 관련 자료는 <파일 · 폴더 · 데이터>에 다 있어. 무엇부터 할지 네가 정하고, 계획을 먼저 보여 준 뒤 진행해.

역할극 대신 도구를 물을 때

<분야>에서 최고 수준의 전문가라면 이 일에 어떤 도구와 방법을 쓸지 먼저 말해 줘. 그다음 그 도구로 <할 일>을 해.

새 세션에서 검사할 때

아래 결과물이 틀렸다는 것을 증명해 봐. 사실 오류, 빠진 경우, 근거 없는 주장을 찾아 심각한 순서로 적어. <결과물 또는 파일 경로>

주의. Rieseberg의 직함은 녹화 당시 기준이다. 반박 검사는 세션을 여러 번 돌리므로 사용량이 늘어난다. 판단이 갈리는 결과물에 먼저 쓴다.
