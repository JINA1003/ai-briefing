Claude Code 2.1.330: 말하면 차트를 그리는 easel, `/loop`는 30일까지 돈다

Claude Code 2.1.330이 11월 20일 나왔다. 차트를 그려 달라고 하면 그려 주고, MCP 지표 결과(예: Prometheus 시계열) 밑에는 자동으로 차트를 붙이는 내장 모드 easel이 생겼다. claude.ai 구독(Pro · Max, 가능한 곳은 Team · Enterprise)에서 macOS와 Linux(WSL 제외)만 된다. 반복 예약 작업과 /loop는 세션이 살아 있는 동안 7일 대신 30일까지 돌고, 이 버전 전에 만든 작업은 여전히 7일에 끝난다. 루트 · 홈 · 최상위 폴더 · 작업 폴더를 겨냥한 rm은 더 많이 승인을 묻고, 답할 사람이 없으면 거절된다.

그래서 무엇을 하나

숫자를 표로 받던 일(커밋 수, 테스트 시간, 지표)을 차트로 그려 달라고 해 본다. 오래 돌리던 /loop · 예약 작업은 업데이트 뒤 다시 만들어야 30일로 늘어난다. 사람 없이 돌리는 작업에 폴더를 지우는 단계가 있으면 멈출 수 있으니 미리 확인한다.

  • claude --version으로 2.1.330 이상인지 확인한다.
  • "이 저장소의 지난 30일 커밋 수를 주별 차트로 그려 줘"처럼 차트를 요청한다.
  • MCP 결과 밑 자동 차트가 거슬리면 /config에서 Auto charts를 끈다. 모드 전체는 /plugin에서 끈다.
  • 예전에 만든 반복 예약 작업과 /loop는 지우고 다시 만들어 30일 기한을 받는다.
  • 그 밖에 긴 대화 압축 직후 몇 분씩 멈추던 문제, WebFetch가 일부 페이지에서 멈추던 문제, ExitWorktree가 다른 세션이 쓰는 worktree를 지우던 문제를 고쳤다.

Signal, OS에 들어간 AI 에이전트가 대화 화면을 못 읽게 막았다

Signal이 11월 20일 휴대폰 OS에 들어간 AI 에이전트가 Signal 대화를 담아 가지 못하게 막는다고 밝혔다. iOS 27에서는 앱 안 스크린샷을 막고, Android에서는 AI 비서가 화면을 읽으려 하면 「화면 보안」 설정을 자동으로 켠다. macOS에서는 스크린샷을 확실히 막을 수 없어 Siri AI를 차단하지 못하고, 대신 Siri 제외 앱 목록에 넣으라고 권한다. 에이전트가 파일 시스템으로 읽는 길은 남아 있어 완전하지 않다고 스스로 적었다. Apple · Google · Microsoft에는 앱이 AI 데이터 접근을 거부할 수 있는 문서화된 방법을 요구했다.

그래서 무엇을 하나

민감한 정보를 다루는 앱을 만든다면 OS의 AI 에이전트가 화면 · 알림 · 파일로 내용을 읽을 수 있다는 점을 위험 목록에 넣는다. 반대로 화면을 읽어 일하는 에이전트를 만든다면 이런 앱에서는 막힌다고 보고 설계한다.

  • macOS 27에서 Signal을 쓰면 시스템 설정 > Siri의 제외 앱(Excluded Apps)에 Signal을 넣는다.
  • 스크린샷이 꼭 필요하면 Signal 설정에서 보호를 끌 수 있다. 이때 내 대화와 상대 대화가 AI 에이전트에 노출될 수 있다고 Signal이 경고한다.
  • 일부 Android 기기는 제조사 제약으로 감지가 안 된다고 Signal이 밝혔다.

Orca (코딩 에이전트 봇을 한 앱에서)

무엇인가

Claude Code · Codex 같은 코딩 에이전트를 내 구독 그대로 여러 개 돌리는 오픈소스 데스크톱 앱이다(MIT). 작업마다 따로 worktree를 만들어 에이전트끼리 부딪히지 않고, Slack · Linear · GitHub나 폰에서 봇에게 일을 맡기면 테스트를 거친 PR로 돌려준다. 내 컴퓨터, SSH 서버, 원격 Orca 서버 어디서든 돌고, 봇이 사람을 필요로 할 때 앱이 부른다. 판에 실린 T3 Code(폰에서 조종) · OpenMausBot(봇 팀)과 같은 갈래다.

왜 지금

지난 7일 별이 6,224개 늘어 총 131,993개다. 11월 21일 v1.4.269에서 봇이 Kiro · Gemini CLI · Goose 등 에이전트 8개 위에서도 돌게 됐고, 11월 22일 v1.4.271에서 짝지은 여러 컴퓨터의 봇을 한 그룹에 묶고 폰 앱에서 에이전트를 끝까지 관리하게 됐다.

설치

brew install --cask stablyai/orca/orca

활용법

  1. 전에는 터미널 탭을 여러 개 열어 Claude Code를 하나씩 띄우고, 어느 탭이 무슨 일을 하는지 기억해야 했다. 이제는 작업마다 worktree를 따로 두고 에이전트를 나란히 돌리며 한 화면에서 상태를 본다. 코디네이터가 큰 일을 쪼개 일꾼 에이전트에게 나눠 주게 할 수도 있다.
  2. Slack · Linear · GitHub에서 봇에게 "이 버그 고쳐 줘"라고 맡기면 테스트를 거친 PR로 돌려받는다. 평일 정해진 시각, PR 열림, 검사 실패 같은 조건에 봇을 걸어 둘 수 있다.
  3. 에이전트가 낸 diff에서 고칠 줄에 메모를 달아 바로 에이전트에게 보낸다. 자리를 비웠을 때는 폰 앱의 "Needs you"에서 도구 승인과 질문에 답한다.

예시 프롬프트

로그인 뒤 프로필 사진이 바뀌지 않는 버그를 고쳐 줘. 원인을 먼저 한 줄로 설명하고, 고친 뒤 관련 테스트를 돌려 통과 결과와 함께 PR로 올려 줘.

주의. 봇은 내 Claude Code · Codex 구독으로 돌아서 요금과 한도는 그 구독을 따른다. Homebrew에서 그냥 orca는 관계없는 Plotly 앱이니 전체 이름을 쓴다. 익명 사용 통계를 모으며, 끄는 법은 orca.dev의 telemetry 문서에 있다. 봇의 성격 · 기억은 SOUL.md · MEMORY.md 평문 파일에 남는다. 봇에게 Slack · GitHub를 연결하기 전에 orca.dev의 봇 보안 문서를 읽는다.

Designed to Scale 활용 팁: AI에게 앱을 맡기기 전에 구조부터 묻기

Dilum Sanjaya가 만든 시스템 설계 인터랙티브 강좌다. 레슨 40개 · 모듈 9개(Foundations, Scaling, Data & Storage, Communication, Reliability, Architecture, Security, Shipping, Whole Systems)로, 브라우저 요청 하나에서 출발해 URL 단축기 · 뉴스피드 · 채팅 앱 전체 설계까지 애니메이션 도표를 한 단계씩 멈추고 다시 보며 따라간다. 21개 언어를 지원한다. 만든 이는 11월 중순 소개 글에서 「시스템 설계를 알면 바이브 코딩으로 만드는 앱도 나아진다. 구조 판단과 AI 프롬프트가 나아진다」라고 했다.

설치 · 설정

  1. 무료 3강부터 본다. designedtoscale.app의 Foundations(요청이 오가는 길 · 지연과 처리량 · 냅킨 계산)는 계정 없이 열린다.
  2. 전에는 "채팅 앱 만들어 줘"라고만 맡기고, 사용자가 늘어 느려진 뒤에야 구조를 고쳤다. 이제는 강좌의 냅킨 계산처럼 예상 사용자 수와 요청 수를 먼저 적고, 캐시 · DB · 큐가 지금 필요한지 AI에게 먼저 묻는다.
  3. 강좌 용어로 지시한다. 로드 밸런서 · 캐시 · 샤딩 · 메시지 큐처럼 레슨에서 본 이름으로 "어디에 무엇을 둘지"를 말하면, AI가 고른 구조를 내가 판단할 수 있다.

실습

만들려는 앱 하나를 놓고, 코드를 쓰기 전에 AI와 구조 설계서 한 장을 만든다.

  1. 무료 레슨 「How a Request Travels」와 「Napkin Math」를 끝까지 눌러 본다.
  2. 만들 앱의 예상 사용자 수와 하루 요청 수를 한 줄로 적는다.
  3. 아래 첫 프롬프트로 Claude Code에 코드 없이 구조안부터 받는다.
  4. Claude가 고른 구성(캐시 · 큐 등)을 강좌의 해당 레슨과 비교한다.
  5. 납득되면 그 설계를 DESIGN.md에 남기고 구현을 맡긴다.

바로 쓰는 프롬프트

새 앱을 맡기기 전에 구조부터

<앱 설명>을 만들려고 해. 예상 사용자는 <사용자 수>, 하루 요청은 <요청 수> 정도야. 코드는 아직 쓰지 말고, 요청이 브라우저에서 DB까지 가는 길을 단계별로 적어 줘. 캐시 · 메시지 큐 · DB 복제가 지금 필요한지 각각 이유와 함께 답해 줘.

규모를 어림할 때

이 앱의 초당 요청 수, 저장 용량, 대역폭을 냅킨 계산으로 어림해 줘. 가정은 표로 먼저 보여 주고, 사용자가 10배가 되면 어디가 먼저 막히는지 짚어 줘.

이미 만든 앱을 점검할 때

이 저장소 구조를 읽고, 사용자가 <목표 규모>로 늘면 먼저 병목이 될 곳 세 군데를 알려 줘. 고칠 순서와 각각 쓸 기법(캐싱 · 샤딩 · 큐 등)을 제안만 하고 코드는 고치지 마.

주의. 가격이 출처마다 다르다. 사이트 요금 페이지는 Foundations 3강만 무료이고 나머지 37강은 Pro(US$4.99, 한 번 결제, 구글 로그인)라고 적었지만, 이용 약관은 「판매가 열리면」이라고 적어 지금 결제가 열렸는지는 확실하지 않다. 「무료 강좌」라는 소개 글과도 엇갈린다. 사이트에는 만든 이 이름이 없고, 만든 이의 소개 글로 확인했다. 「X 소개 글 이틀 만에 조회 40만」은 확인 안 됨이다.
