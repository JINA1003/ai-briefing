Claude Code 2.1.310~2.1.314: 쉬던 대화는 자동 요약, ultrathink는 xhigh로

2.1.314에서 유휴 압축(idle compaction)이 VS Code와 Claude Desktop의 Code 탭으로 넓어졌습니다. 200K 토큰이 넘는 대화를 쉬게 두면 요약해 두고, 프롬프트 캐시가 만료됐을 때 다음 메시지에 그 요약을 씁니다. 2.1.311부터는 터미널에서 ultrathink를 쓰면 Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable 5.1에서 그 턴이 xhigh effort로 돕니다. 같은 버전에서 200K를 넘긴 표준 컨텍스트 세션이 "Usage credits required for 1M context"로 멈추던 문제도 고쳐져, 이제는 대화를 압축하고 이어 갑니다. 2.1.310은 Monitor 도구를 Bedrock, Vertex, Foundry에서도 쓸 수 있게 했습니다.

그래서 무엇을 하나

claude --version으로 버전을 확인하고 업데이트합니다. 쉬는 동안 토큰이 쓰이는 게 싫으면 설정에서 idleCompaction을 false로 둡니다.

  • claude --version으로 2.1.314 이상인지 확인합니다.
  • 어려운 턴에서만 프롬프트에 ultrathink를 넣어 effort를 올립니다.
  • 유휴 압축을 끄려면 settings.json에 "idleCompaction": false를 넣습니다(v2.1.290 이상).

Claude Code 긴 세션 관리법: 유휴 압축 · 프롬프트 캐시 · /compact로 사용량 줄이기

Claude Code는 요청마다 전체 대화를 다시 보내고, 프롬프트 캐시가 그 반복분을 싸게 처리합니다. 캐시는 쉬는 시간이 지나면 만료되고, 만료 뒤 첫 메시지는 전체 컨텍스트를 다시 처리합니다. 2.1.314는 유휴 압축을 VS Code와 Desktop까지 넓혀, 200K 토큰 넘는 대화를 쉬는 동안 요약해 둡니다. 공식 문서의 비용 · 캐시 안내를 따라 긴 세션을 관리하는 순서를 정리했습니다.

설치 · 설정

  1. claude --version으로 2.1.314 이상인지 확인합니다.
  2. 세션 중 /usage를 열어 Prompt cache (main) 줄의 캐시 비율과 miss 수를 봅니다.
  3. 모델과 effort는 세션 시작 때 정하고 작업 중에는 바꾸지 않습니다.
  4. 프로젝트 루트 CLAUDE.md에 # Compact instructions 섹션을 만들고 압축 때 남길 내용을 적습니다.
  5. 쉬는 동안 자동 요약을 원치 않으면 settings.json에 "idleCompaction": false를 넣습니다.
  6. API 키로 쓰고 쉬었다 돌아오는 일이 잦으면 promptCacheTtl을 1h로 둡니다.

실습

작업 하나를 끝내고 다음 작업으로 넘어갈 때 비용이 적게 드는 정리 루틴을 만들어 봅니다.

  1. 작업 하나를 마치면 /usage로 캐시 상태가 warm인지 봅니다.
  2. 다음 작업이 이어지는 일이면 캐시가 따뜻할 때 /compact <남길 내용>을 실행합니다.
  3. 다음 작업이 무관한 일이면 /rename <이름>으로 세션 이름을 붙입니다.
  4. /clear로 새로 시작합니다.
  5. 잘못된 방향으로 간 대화는 /compact 대신 /rewind로 이전 턴으로 돌아갑니다.
  6. 하루 뒤 /usage의 추천 줄을 보고 f를 눌러 적용할 수 있는 것을 적용합니다.

압축 전에 남길 것 정하기

/compact <지금 고치고 있는 파일 경로>와 테스트 실패 메시지, 이미 결정한 설계만 남겨 줘

CLAUDE.md 압축 지침 만들기

이 프로젝트 CLAUDE.md에 '# Compact instructions' 섹션을 추가해 줘. 압축할 때 <테스트 출력과 코드 변경>을 우선 남기라고 적고, 바꾸기 전에 diff를 보여 줘.

CLAUDE.md 다이어트

CLAUDE.md를 읽고 특정 작업(<PR 리뷰, DB 마이그레이션>)에만 필요한 지침을 골라 줘. 각각을 스킬로 옮기는 안을 보여 주고, CLAUDE.md는 200줄 아래로 줄이는 계획을 세워 줘. 파일은 아직 고치지 마.

안 될 때

200K를 넘긴 표준 컨텍스트 세션이 "Usage credits required for 1M context"로 멈춥니다.
2.1.311에서 고쳐졌습니다. 업데이트하면 대화를 압축하고 이어 갑니다.
세션 중에 CLAUDE.md를 고쳤는데 Claude가 옛 내용대로 움직입니다.
루트와 사용자 CLAUDE.md는 세션 시작 때 한 번 읽습니다. /clear, /compact, 재시작 뒤에 반영됩니다.
PreCompact 훅 출력이 커서 압축이 실패하거나 반복됩니다.
2.1.314부터 각 훅 출력을 10,000자에서 자릅니다. 업데이트합니다.

주의. /compact는 요약할 대화를 다시 읽는 큰 요청이라, 캐시가 만료된 뒤에 하면 비쌉니다. 유휴 압축과 세션 요약은 쉬는 동안에도 토큰을 씁니다. 1시간 TTL은 캐시 쓰기 단가가 더 높아, 5분 안에 끝나는 짧은 작업에는 손해입니다.

Karpathy 지침 CLAUDE.md 설치 · 사용법: 과한 코드와 엉뚱한 수정 줄이기

Andrej Karpathy가 지적한 LLM 코딩의 흔한 실수를 막으려고 만든 CLAUDE.md 한 장입니다. 코딩 전에 생각하기, 단순함 먼저, 필요한 곳만 고치기, 목표로 실행하기의 네 원칙을 담았습니다. 지난주 GitHub에서 별 4,250개를 받았습니다. 스킬을 새로 배우지 않고 CLAUDE.md로 작업 방식을 바꾸는 가장 짧은 길입니다.

설치 · 설정

curl -o CLAUDE.md https://raw.githubusercontent.com/forrestchang/andrej-karpathy-skills/main/CLAUDE.md
  1. 새 프로젝트라면 프로젝트 루트에서 위 curl 명령으로 CLAUDE.md를 받습니다.
  2. 기존 CLAUDE.md가 있으면 덮어쓰지 말고 README의 덧붙이기 명령(echo "" >> CLAUDE.md 뒤 curl ... >> CLAUDE.md)을 씁니다.
  3. 모든 프로젝트에 쓰려면 Claude Code에서 /plugin marketplace add forrestchang/andrej-karpathy-skills를 실행합니다.
  4. 이어서 /plugin install andrej-karpathy-skills@karpathy-skills를 실행합니다.
  5. 받은 파일 아래에 ## Project-Specific Guidelines 섹션을 만들고 프로젝트 규칙을 덧붙입니다.

실습

같은 버그 수정을 지침 적용 전후로 시켜 보고 diff 크기와 질문 시점을 비교합니다.

  1. 지침을 넣기 전, 작은 버그 하나를 Claude에게 고치게 하고 git diff --stat을 적어 둡니다.
  2. git stash로 변경을 치웁니다.
  3. CLAUDE.md에 지침을 넣고 새 세션을 엽니다.
  4. 같은 버그를 "재현 테스트를 먼저 쓰고 통과시켜"라는 목표로 다시 시킵니다.
  5. 구현 전에 질문이 나왔는지, git diff --stat이 줄었는지 비교합니다.

바로 쓰는 프롬프트

애매한 요청을 먼저 좁히기

<기능 요청>을 구현하기 전에 네가 세운 가정과 가능한 해석을 먼저 나열해 줘. 내가 고르기 전에는 코드를 쓰지 마.

검증 가능한 계획 세우기

<버그 설명>을 고쳐 줘. 먼저 재현하는 테스트를 쓰고, 단계마다 '→ verify: 확인 방법' 형식으로 짧은 계획을 보여 준 뒤 진행해.

diff 점검

지금 diff에서 내 요청(<요청 요약>)으로 설명되지 않는 변경을 모두 찾아 줘. 네 변경 때문에 안 쓰이게 된 import · 변수만 지우고, 원래 있던 죽은 코드는 목록으로만 알려 줘.

주의. 저장소는 multica-ai 아래에 있지만 README의 설치 명령은 forrestchang/andrej-karpathy-skills 경로를 가리킵니다. 실행 전에 받은 파일 내용을 확인합니다. README는 이 지침이 속도보다 신중함을 택한다고 적었으니, 오타 수정 같은 사소한 작업에는 판단해서 씁니다.
