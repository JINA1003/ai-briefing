Claude Code 2.1.314: 작업 디렉터리 밖 쓰기 차단 설정 추가

2.1.314에 permissions.blockWritesOutsideWorkingDirectories 설정이 추가됐습니다. 켜면 Write, Edit, NotebookEdit가 모든 권한 모드에서 작업 디렉터리 밖 경로를 거부합니다. VS Code와 Claude Desktop의 Code 탭에는 유휴 압축(idle compaction)이 들어왔습니다. 200K 토큰이 넘는 대화를 한동안 두면 요약해 두었다가, 프롬프트 캐시가 만료됐을 때 다음 메시지에 그 요약을 씁니다. claude -p는 시작에 실패하면 이제 오류를 출력하고 종료 코드 1을 반환합니다. 예전에는 출력 없이 0으로 끝났습니다.

그래서 무엇을 하나

auto 모드나 권한 우회 모드를 자주 쓴다면 settings.json에 이 설정을 켜 두세요. claude -p를 스크립트에서 돌린다면 종료 코드 검사가 이제 실패를 잡아낸다는 점을 확인하세요.

  • claude update로 2.1.314 이상으로 올린다
  • ~/.claude/settings.json의 permissions 안에 "blockWritesOutsideWorkingDirectories": true를 넣는다
  • /permissions의 "Recently blocked" 탭에서 막힌 요청을 확인한다

Anthropic, Agent Skills 표준을 Agentic AI Foundation에 기증

Anthropic이 10월 22일 Agent Skills의 이름, 로고, GitHub 조직, agentskills.io 도메인을 Agentic AI Foundation(AAIF)에 기증했습니다. AAIF는 Linux Foundation 산하 단체이고, MCP도 이미 이곳에 기증돼 있습니다. Anthropic에 따르면 70개가 넘는 에이전트 플랫폼이 이 표준을 쓰고 있고, 공개된 스킬은 100만 개, 설치는 약 2억 8천만 회입니다. 초기 로드맵 안에는 버전 릴리스, 공식 제안 절차, 보안 지침이 들어 있습니다.

그래서 무엇을 하나

직접 만든 스킬을 계속 SKILL.md 폴더 형식으로 유지하면 Claude Code 밖 도구에서도 그대로 쓸 수 있습니다. 앞으로 나올 보안 지침은 agentskills.io에서 확인하세요.

백그라운드 에이전트 상태 요약이 비용의 16%를 차지한다는 측정 (HN 566점)

외부 측정 · 보도Flamerix AI의 gist에 따르면 Claude Code는 백그라운드 에이전트마다 약 30초 간격으로 기록 전체를 그 에이전트의 모델에 보냅니다. 3~5단어 상태 요약을 받아 에이전트 패널에 표시하는 용도입니다. 작성자는 OpenTelemetry의 query_source별 집계로 이 호출이 Claude Code 지출의 16.4%, API 요청의 19.7%라고 측정했습니다. 그 지출의 96%가 Opus에서 나왔습니다. Anthropic의 공식 확인은 아니며, 한 댓글 작성자의 재측정에서는 약 8%였습니다.

그래서 무엇을 하나

백그라운드 에이전트를 많이 쓴다면 OTEL 내보내기를 켜고 query_source별 비용을 직접 확인해 보세요. gist에 따르면 agentProgressSummaries: false로는 꺼지지 않습니다. gist의 런타임 패치는 작성자도 약관과 충돌할 수 있다고 경고하므로 권하지 않습니다.

Cloudflare security-audit 스킬 설치 · 사용법: 내 저장소를 6단계로 보안 감사하기

Cloudflare가 공개한 코딩 에이전트용 스킬로, 에이전트에게 보안 감사를 맡깁니다. Cloudflare 취약점 탐지 하네스의 출발점이 된 단일 저장소 버전입니다. 후보마다 새 검증 에이전트가 반증을 시도하고, 남은 것만 confirmed로 기록합니다. 지난주 설치가 16,762회로 직전 3주 평균 6,319회의 2.7배였고, 지난 7일 중 5일 GitHub 트렌딩에 올랐습니다.

설치 · 설정

npx skills add https://github.com/cloudflare/security-audit-skill \
  --skill security-audit
  1. Node.js가 설치돼 있는지 node --version으로 확인한다. 검증 스크립트를 돌릴 때 필요하다
  2. 감사할 저장소 루트에서 위 설치 명령을 실행한다
  3. 모든 프로젝트에서 쓰려면 같은 명령 끝에 --global을 붙인다
  4. 에이전트 선택이나 비대화형 옵션은 npx skills --help로 확인한다

실습

작은 저장소 하나를 감사하고 confirmed, needs_validation, rejected 판정을 읽어 본다

  1. 감사할 저장소에서 claude를 실행한다
  2. security audit this codebase라고 입력한다. 요청이 트리거와 맞으면 스킬이 자동으로 켜진다
  3. 1단계 정찰이 끝나면 architecture.md와 coverage-ledger.json이 생성된다
  4. 끝나면 ~/security-audit-skill/<repo-name>/run-<N>을 연다
  5. REPORT.md부터 읽고, 세부는 FINDINGS-DETAIL.md에서 본다
  6. NEEDS-VALIDATION.md에 남은 항목은 사람이 직접 확인한다
  7. 같은 저장소에 한 번 더 실행한다. 실행 결과는 누적된다

바로 쓰는 프롬프트

처음 써 볼 때

security audit this codebase

특정 폴더만 볼 때

find security vulnerabilities in <./src>

보고서 위치를 정할 때

do a security review, output to <~/audits/my-project>

안 될 때

후보가 confirmed가 되지 않고 needs_validation으로만 남는다
README에 따르면 외부 네트워크 차단, 허용 목록 환경, 자원 제한, 지정 경로만 쓰기 같은 OS 수준 샌드박스가 없으면 대상 코드를 실행하지 않고 needs_validation으로 둡니다. 샌드박스를 갖춘 환경에서 다시 실행하세요.
한 번 실행으로 찾은 취약점이 적다
Cloudflare 테스트에서 한 번 실행은 여러 번 실행해 찾은 전체의 약 절반만 찾았습니다. 같은 저장소에 여러 번 실행하세요. 결과는 누적됩니다.

주의. 병렬 서브에이전트와 도구 사용을 지원하는 모델이 필요하고, 여러 번 실행해야 해서 토큰 사용량이 늘어납니다. 대상 코드를 실행하는 검증은 외부 네트워크를 끊은 OS 수준 샌드박스에서만 하라고 README가 요구합니다. 결과는 기본으로 저장소 밖에 쓰이고, 저장소 안에는 버전 관리에서 무시되는 경로를 지정했을 때만 씁니다.

이런 분께
직접 관리하는 저장소의 보안 점검을 미뤄 온 개발자
읽고 나면
한 줄 요청으로 내 저장소의 감사 보고서와 기계가 읽을 수 있는 findings.json을 얻습니다.

SkillSpector 설치 · 사용법: 스킬을 깔기 전에 위험 점수부터 보기

NVIDIA가 공개한 에이전트 스킬 보안 스캐너입니다. 프롬프트 인젝션, 데이터 유출, 공급망, MCP 도구 오염 등 17개 분류, 71개 취약점 패턴을 검사합니다. 지난 7일 중 3일 GitHub 트렌딩에 올랐습니다. 스킬 설치가 쉬워진 만큼, 깔기 전에 한 번 거르는 습관을 들이기 좋습니다.

설치 · 설정

uv tool install git+https://github.com/NVIDIA/skillspector.git
  1. uv가 없다면 먼저 설치한다
  2. 위 설치 명령으로 skillspector를 설치한다
  3. 처음에는 --no-llm으로 로컬 정적 검사만 돌린다
  4. LLM 분석을 쓰려면 SKILLSPECTOR_PROVIDER=anthropic과 ANTHROPIC_API_KEY를 설정한다
  5. Claude Code에서 쓰려면 claude mcp add skillspector -- skillspector mcp로 MCP 서버를 등록한다

실습

설치하려던 스킬 하나를 검사하고, 검토가 끝난 항목은 baseline으로 묶는다

  1. skillspector scan https://github.com/<user>/<my-skill> --no-llm으로 원격 저장소를 검사한다
  2. 점수와 권고를 본다. 0~20은 SAFE, 21~50은 CAUTION, 51 이상은 DO NOT INSTALL이다
  3. skillspector scan ./my-skill/ --format markdown --output report.md로 보고서를 파일로 남긴다
  4. 검토가 끝난 지적은 skillspector baseline ./my-skill/ -o .skillspector-baseline.yaml로 저장한다
  5. 다음부터 skillspector scan ./my-skill/ --baseline .skillspector-baseline.yaml로 새 지적만 본다
  6. ~/.claude/skills/를 통째로 보려면 skillspector scan ~/.claude/skills/ --recursive --no-llm --format json을 쓴다

바로 쓰는 프롬프트

설치 전 한 개 검사

skillspector MCP로 <https://github.com/user/my-skill>을 검사하고, 점수와 권고, CRITICAL·HIGH 지적만 한국어로 정리해 줘.

이미 깐 스킬 점검

skillspector로 <~/.claude/skills/> 아래 스킬을 전부 검사해서, CAUTION 이상인 것만 표로 보여 줘. 각 행에 스킬 이름, 점수, 가장 심각한 지적을 넣어.

오탐 정리

<./my-skill/>의 skillspector 지적을 하나씩 코드와 대조해서 실제 위험과 오탐으로 나눠 줘. 오탐만 baseline에 넣는 명령을 알려 줘.

안 될 때

지원하지 않는 설정을 거부하는 모델을 지정하면 검사가 종료 코드 2로 멈춘다
SKILLSPECTOR_MODEL을 다른 모델로 바꾸거나 --no-llm으로 정적 검사만 돌립니다.
느린 머신에서 의존성 분석이 일부만 끝난다
SKILLSPECTOR_MAX_DEPENDENCY_SOURCE_ANALYSIS_SECONDS 값을 늘립니다.
100MiB가 넘는 입력에서 IngestLimitExceededError가 난다
입력 크기 제한입니다. --exclude로 테스트 데이터 같은 큰 파일을 빼고 검사합니다.

주의. LLM 분석이 기본으로 켜져 있어서 파일 내용이 설정한 제공자에게 전송됩니다. 내용을 밖으로 보내지 않으려면 --no-llm을 쓰세요. 다만 --no-llm에서도 의존성 이름과 버전은 OSV.dev로 전송됩니다. 정적 단계는 오탐이 있고, 실행 중 동작, 영어 외 텍스트, 이미지 속 글자는 검사하지 못합니다. HTTP MCP 전송에는 인증이 없습니다. 샌드박스가 아니므로 검사를 통과했다고 안전하게 실행되는 것은 아닙니다.
