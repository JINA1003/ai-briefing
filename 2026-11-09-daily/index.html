MCP 공식 서버 v2.4.0: filesystem · git · fetch 취약점 6개 수정

modelcontextprotocol/servers v2.4.0이 서버 세 개의 취약점 6개를 고쳤어요. filesystem 서버는 검사 도중 폴더를 심볼릭 링크로 바꿔치기하면 허용 폴더 밖 파일을 읽거나 들여올 수 있었어요. git 서버는 신뢰할 수 없는 저장소를 읽기만 해도 .git/config에 적힌 프로그램이 서버 권한으로 실행될 수 있었고, --repository 제한도 우회됐어요. fetch 서버는 IPv6 사설 주소를 공개 주소로 보거나, 같은 경로를 다르게 써서 robots.txt 금지를 피할 수 있었어요. 고친 버전은 filesystem 2.3.0, git · fetch 2026.11.11이에요.

그래서 무엇을 하나

우리 팀에게는: Claude Code에 이 서버들을 붙여 쓰는 사람은 오늘 버전을 올려야 해요. 특히 남의 저장소를 git 서버로 읽게 하는 경우가 위험해요.

  • claude mcp list로 연결된 MCP 서버와 패키지 이름을 확인한다.
  • filesystem을 날짜 버전(2025.1.14~2026.8.31)으로 쓰면 패키지 관리자가 2.3.0을 업그레이드로 보여 주지 않는다. npm install @modelcontextprotocol/server-filesystem@2.3.0으로 직접 지정한다.
  • mcp-server-git · mcp-server-fetch는 2026.11.11 이상으로 올린다(2026.11.4까지 영향).
  • git 서버는 이제 Git 2.31 미만을 거부한다. git --version으로 먼저 확인한다.

AWS, 에이전트 무리가 만든 로컬 AWS 에뮬레이터 공개

AWS가 aws-emulator를 공개했어요. AWS 계정 없이 내 PC나 CI에서 AWS API를 흉내 내 테스트하는 도구이고, 라이선스는 CC0예요. AWS의 Swami Sivasubramanian은 공개 API 모델 400여 개로 서비스 200여 개를 다룬다고 썼어요. 만드는 방식이 눈에 띄어요. 에이전트가 실제 AWS에서 통과하는 테스트를 먼저 만들고, 에뮬레이터가 같은 테스트를 통과할 때까지 고친 뒤, 보안 에이전트 리뷰가 낀 머지 게이트를 거쳐요. Simon Willison은 첫 3주 커밋이 29,684개였다고 전했어요.

그래서 무엇을 하나

우리 팀에게는: AWS를 쓰면 클라우드 비용 없이 에이전트가 고친 코드를 바로 돌려 볼 수 있어요. AWS를 안 써도 "에이전트에게 스스로 검증할 수단부터 준다"는 교훈은 그대로 가져갈 만해요. 글에는 검증 수단 없이 나흘 밤을 감독했던 일이, 명세와 시험 환경을 주자 두 시간에 끝났다는 사례가 있어요.

  • 에이전트용 스킬로 설치한다(AWS CLI 2.35.0 이상): aws agent-toolkit add-skill --skill-name aws-emulator --region us-east-1
  • macOS에서는 지금 Docker가 필요하다.
  • 저장소의 things-that-do-not-work 폴더에서 실제 AWS와 다르게 동작하는 부분을 먼저 확인한다.
  • 개발 · 테스트용이다. 운영이나 보안 테스트에는 쓰지 않는다.

Gemini Decisions API: 글 대신 보기 중 하나를 고르는 판단 전용 API

Google이 판단 전용 엔드포인트 Gemini Decisions API를 내놨어요. 모델은 gemini-decision-1이고, 답을 글로 생성하지 않고 정해진 보기에 확률과 0~1 신뢰도를 매겨요. 입력 하나(글 · 이미지 · 오디오 · 영상 · PDF, 최대 256K 토큰)에 질문을 최대 1,000개까지 한 번에 묻고, 질문 형식은 예/아니오 · 객관식(보기 2~255개) · 등급 점수 세 가지예요. 요금은 입력 100만 토큰당 0.10달러이고 출력은 무료이며, 공유 입력은 질문 수와 상관없이 한 번만 계산해요. 지연은 전체 150~250ms이고 Gemini API와 Google AI Studio에서 쓸 수 있어요.

그래서 무엇을 하나

우리 팀에게는: 도구 고르기, 모델 라우팅, 규칙 위반 검사, 답안 채점처럼 '정해진 보기 중 고르는' 일을 LLM 생성으로 하고 있다면 더 싸고 빠른 대안이에요. AI Studio 무료 등급으로 먼저 시험해 보세요.

  • Google AI Studio에서 API 키를 받는다.
  • Decisions API 문서의 Python · JavaScript · REST 가이드 중 하나를 따라 google-genai SDK로 첫 요청을 보낸다.
  • 지금 LLM에 시키는 분류 작업 하나를 골라 같은 입력에 질문 여러 개를 묶어 보내고, 비용과 정확도를 비교한다.

무엇인가

코딩 에이전트를 돌리기 위한 터미널 작업 공간이에요. Rust 단일 실행 파일로 지금 쓰는 터미널 안에서 돌아요. Claude Code · Codex · Cursor · OpenCode 등을 감싸지 않고 그대로 띄우고, 창마다 일하는 중 · 막힘 · 쉼 상태를 표시해 답이 필요한 에이전트를 알려 줘요.

왜 지금

한 주 동안 별이 2,196개 늘었어요. herdr를 iPhone · iPad에서 SSH로 보고 조종하는 짝 앱 Heeler(ZingerLittleBee/Heeler)도 지난 7일 중 4일 GitHub 트렌딩에 올랐어요.

설치

brew install herdr

활용법

  1. herdr로 시작하고 창을 나눠 Claude Code와 Codex를 나란히 띄운다. 전에는 터미널 탭을 하나씩 열어 누가 멈췄는지 확인했다면, 이제는 상태 표시만 보고 막힌 창으로 간다. 식당 주문 화면에서 '호출' 불이 켜진 테이블만 가는 것과 같아요.
  2. 긴 작업을 걸어 두고 ctrl+b q로 빠져나온다. 노트북을 닫거나 SSH가 끊겨도 터미널은 백그라운드 서버에서 계속 돌고, 다시 herdr를 치면 그대로 붙는다.
  3. 저장해 둔 SSH 머신을 더하면 내 PC와 개발 서버의 에이전트가 한 목록에 모인다. 에이전트끼리 CLI · 소켓 API로 창을 띄우고 서로에게 프롬프트를 보내게 할 수도 있다.

예시 프롬프트

지금 herdr 안에서 돌고 있어. 옆 창에 Codex 에이전트를 하나 띄워서 <기능 이름>의 테스트를 쓰게 하고, 너는 구현을 맡아. Codex가 막히면(blocked) 그때 나에게 알려 줘.

주의. 재시작하면 창 배치는 복원되고 지원 에이전트 세션은 이어서 열 수 있지만, 원래 프로세스는 살아남지 않아요. curl ... | sh 설치 스크립트를 쓴다면 내용을 먼저 읽어 보세요. README에는 내려받은 파일을 검증하는 방법이 없어요.

Claude Whiteboards · Sheets 베타 출시, Dashboards는 Claude Data로 바꿔 정식 출시

Anthropic이 팀이 Claude와 함께 쓰는 도구 세 가지를 내놓았습니다. Whiteboards(베타)는 회고 메모를 주제별로 묶고 담당자 · 날짜가 붙은 타임라인을 만들며, 완성한 보드를 문서 · 슬라이드로 바꾸거나 Lucid · Miro로 옮깁니다. Sheets(베타)는 탭 · 수식 · 서식 · 드롭다운이 있는 시트를 만들고, Claude가 고친 칸을 변경으로 표시합니다. Claude Data는 Claude Dashboards의 새 이름으로 정식 출시됐고, 웨어하우스 · CRM 데이터에 질문해 대시보드와 데이터 스토리를 만듭니다. 세 가지 모두 모든 유료 플랜의 웹 · 데스크톱 · 모바일에서 씁니다.

그래서 무엇을 하나

Team 플랜이면 이미 켜져 있으니 이번 주 회의 메모 하나를 Whiteboards로 타임라인까지 바꿔 보세요. Enterprise는 Whiteboards · Sheets가 기본으로 꺼져 있어 관리자가 켜야 하고, Claude Data는 11월 19일부터 기본으로 켜집니다.

  • 관리자는 Organization settings > Artifacts에서 세 도구의 켜짐 여부를 확인한다.
  • 대화에서 계획을 설명하고 보드로 만들어 달라고 한 뒤, 보드 일부를 끌어 선택해 질문한다.
  • Sheets는 「채용 예산」처럼 요청한다. 간단한 표 기능만 있으니 복잡한 계산은 .xlsx나 CSV로 내보내거나 Claude for Excel을 쓴다.
  • Claude Data는 웨어하우스나 CRM 커넥터를 먼저 연결한다. 공유받은 사람은 승인한 쿼리의 결과만 보고, 내 권한으로 다른 쿼리를 돌리지 못한다.

Vercel Labs의 에이전트용 브라우저 자동화 CLI인 agent-browser가 v0.42.0을 냈습니다. 새 saved flows(실험 기능)는 브라우저 작업을 한 번 녹화해 두고 그 요청을 다시 재생합니다. 재생할 때는 직접 HTTP 요청, 페이지 안에서 같은 요청, 녹화한 명령 재생 순서로 시도하고, 성공한 방식을 저장합니다. 재생 요청은 공개 주소로만 보냅니다. 핵심 스킬 지침도 스크린샷보다 페이지 구조 스냅샷을 먼저 쓰도록 바뀌었고, Node 22 이상이 필요합니다.

그래서 무엇을 하나

매번 같은 화면을 눌러 값을 확인하는 일이 있으면 한 번 녹화해 두고 재생으로 바꿔 보세요. 화면을 다시 그리지 않고 요청만 보내는 단계부터 시도하니 반복 작업이 빨라질 수 있습니다. 실험 기능이라 결과는 직접 확인합니다.

  • Node 버전이 22 이상인지 확인한 뒤 agent-browser를 v0.42.0으로 올린다.
  • 녹화 · 재생 명령 이름은 릴리스 노트에 없으니 저장소 README의 saved flows 절을 보고 쓴다.

agent-desktop

무엇인가

AI 에이전트가 데스크톱 앱을 직접 조작하게 해 주는 Vercel Labs의 CLI다. 화면을 찍어 픽셀을 맞추는 대신 앱의 접근성 트리를 JSON으로 읽고, 요소마다 붙은 참조(ref)로 클릭 · 입력한다. 조작 뒤 다시 읽어 결과를 확인하는 루프는 Claude Code 같은 에이전트가 돌린다. macOS 13 이상, Windows 10, Ubuntu 24.04 이상을 지원하고 Apache-2.0이다.

왜 지금

지난 7일 별이 9,989개 늘어 1만 9,654개가 됐고, 이번 주 GitHub 트렌딩 주간 증가(13,712개)가 후보 중 가장 컸다. 11/5 v1.2.0에서 agent-desktop mcp가 들어와 MCP 서버로도 붙일 수 있다.

설치

npm install -g agent-desktop

활용법

  1. 설치 뒤 agent-desktop status로 상태를 보고, agent-desktop permissions --guide를 따라 macOS 손쉬운 사용 권한을 준다.
  2. Claude Code에 붙이려면 스킬(npx skills add https://github.com/vercel-labs/agent-desktop --skill agent-desktop)을 깔거나, MCP 설정에 agent-desktop mcp를 등록한다.
  3. 전에는 웹이 아닌 데스크톱 앱(설정 창, 사내 프로그램)은 사람이 직접 눌러 확인했다. 이제는 Claude가 snapshot으로 화면 구조를 읽고, ref로 누르고, 다시 읽어 결과까지 확인한다. 브라우저 자동화의 데스크톱판이라고 보면 된다.

예시 프롬프트

agent-desktop으로 <앱 이름>의 누를 수 있는 요소를 `agent-desktop snapshot --app <앱 이름> -i`로 보여 줘. 그다음 <메뉴 이름>을 누르고, 다시 snapshot을 찍어 바뀐 점을 확인해 단계별로 알려 줘.

주의. 스냅샷 · 클립보드 · 스크린샷에 개인 정보가 담길 수 있어 공개 로그에 올리지 말라고 README가 경고한다. 기본은 실제 입력 없이 동작하고, --headed를 줘야 실제 마우스 · 키 입력을 쓴다. 비밀번호 같은 값은 --stdin으로 넘긴다.

Microsoft Foundry azd 확장 1.0

무엇인가

Azure Developer CLI(azd)에 Microsoft Foundry 에이전트 작업을 더하는 확장 묶음 microsoft.foundry가 11/5 1.0 정식(GA)이 됐다. 에이전트 코드와 배포 설정(azure.yaml)을 같은 저장소에 두고, 초기화 · 로컬 시험 · 배포 · 점검을 명령으로 이어 간다. 평가 확장을 더하면 테스트 데이터와 채점 기준을 만들어 품질 검사를 CI/CD에 붙인다.

왜 지금

베타였던 에이전트 확장이 1.0이 됐다. 11/9 판에 실린 microsoft-foundry 스킬과 짝이다. 공식 글은 Claude Code 같은 코딩 에이전트가 Foundry 스킬로 프로젝트 뼈대를 만들게 하는 방법도 함께 안내한다.

설치

azd ext install microsoft.foundry

활용법

  1. azd auth login으로 로그인한 뒤 확장을 설치한다. azd 1.37.0 이상이 필요하고, 예제는 Python 3.13 이상과 uv를 쓴다.

  3. 운영 중에는 azd ai agent monitor --follow로 로그를 보고 azd ai agent doctor로 점검한다. azd ext install azure.ai.evaluations를 더하면 azd ai eval run start --eval quality로 배포 전 품질 검사를 돌린다.

예시 프롬프트

주의. Azure 구독, Foundry 권한, 고른 리전의 모델 할당량이 필요하다. 만든 리소스와 모델 사용에는 Azure 요금이 들고, 로컬 시험도 Azure 모델 배포를 부르므로 돈이 든다. 새 프로젝트에서 azd down은 리소스 그룹 전체를 지운다.

Claude Code 2.1.319: MCP 작업 백그라운드 처리, 확인 대신 거절하는 권한 설정

MCP 서버가 도구 호출을 task로 실행하면 Claude Code가 이를 바로 백그라운드로 보내고, 끝나면 결과를 Claude에게 알려요. permissions.denyInsteadOfPrompting을 켜면 확인 창을 기다릴 도구 호출을 바로 거절하고 턴을 이어가요. 이 설정은 터미널 세션, 서브에이전트, 팀원 세션에 모두 적용돼요. Bash 권한 우회, sed 권한 확인 누락, 워크트리 생성 때 샌드박스 탈출 같은 보안 문제도 고쳤어요. 스스로 간격을 정하는 /loop는 이제 다음 실행을 잡지 않고 끝난 턴에서 멈춰요.

그래서 무엇을 하나

업데이트한 뒤 자리를 비우고 돌리는 세션에 denyInsteadOfPrompting을 켜 보세요. 확인 창 하나 때문에 밤새 멈춰 있던 일이 줄어요.

  • settings.json의 permissions에 "denyInsteadOfPrompting": true를 넣어요.
  • MCP 작업을 도구 호출 안에서 끝까지 기다리게 하려면 CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND를 설정해요.
  • MCP task 기능을 아예 끄려면 CLAUDE_CODE_DISABLE_MCP_TASKS=1을 설정해요.
  • /loop의 예전 동작이 필요하면 CLAUDE_CODE_LOOP_KEEPALIVE=1을 설정해요.
