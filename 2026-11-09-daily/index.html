Claude Code 2.1.319: MCP 작업 백그라운드 처리, 확인 대신 거절하는 권한 설정

MCP 서버가 도구 호출을 task로 실행하면 Claude Code가 이를 바로 백그라운드로 보내고, 끝나면 결과를 Claude에게 알려요. permissions.denyInsteadOfPrompting을 켜면 확인 창을 기다릴 도구 호출을 바로 거절하고 턴을 이어가요. 이 설정은 터미널 세션, 서브에이전트, 팀원 세션에 모두 적용돼요. Bash 권한 우회, sed 권한 확인 누락, 워크트리 생성 때 샌드박스 탈출 같은 보안 문제도 고쳤어요. 스스로 간격을 정하는 /loop는 이제 다음 실행을 잡지 않고 끝난 턴에서 멈춰요.

그래서 무엇을 하나

업데이트한 뒤 자리를 비우고 돌리는 세션에 denyInsteadOfPrompting을 켜 보세요. 확인 창 하나 때문에 밤새 멈춰 있던 일이 줄어요.

  • settings.json의 permissions에 "denyInsteadOfPrompting": true를 넣어요.
  • MCP 작업을 도구 호출 안에서 끝까지 기다리게 하려면 CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND를 설정해요.
  • MCP task 기능을 아예 끄려면 CLAUDE_CODE_DISABLE_MCP_TASKS=1을 설정해요.
  • /loop의 예전 동작이 필요하면 CLAUDE_CODE_LOOP_KEEPALIVE=1을 설정해요.

Claude Code가 웹 검색 때 계정 이메일을 보낸다는 이슈, HN 1,601점

외부 측정 · 보도한 사용자가 2.1.318에서 Claude Code가 웹 검색을 하며 User-Agent 헤더에 자기 이메일을 실어 제3자 사이트에 보냈다고 이슈를 올렸어요. 이 글은 HN에서 1,601점, 댓글 532개를 받았어요. Anthropic 쪽 기여자는 2.1.317부터 기본으로 켜진 내장 mod cc-plugin-privacy가 이를 막는다고 답했고, 빠진 경우가 있으면 알려 달라고 했어요. 제보자가 그보다 새 버전을 쓰고 있어서, 모든 경우를 막는지는 아직 확인되지 않았어요. 이슈는 아직 열려 있어요.

그래서 무엇을 하나

/plugins에서 cc-plugin-privacy가 켜져 있는지 확인하세요. 버전이 2.1.317보다 낮으면 먼저 업데이트하세요.

  • claude --version으로 2.1.317 이상인지 확인해요.
  • /plugins를 열어 cc-plugin-privacy가 켜져 있는지 봐요.

grill-with-docs

무엇인가

Matt Pocock 스킬 모음에 든 스킬이에요. 계획이나 설계를 에이전트가 끝까지 질문으로 따져 묻는 grill-me에, 프로젝트 용어집과 ADR(결정 기록) 정리를 더했어요. 실제 동작은 grilling과 domain-modeling 두 스킬을 차례로 부르는 방식이에요.

왜 지금

skills.sh 종합 상위 20위에 4위로 새로 들어왔어요. 저장소 mattpocock/skills는 7일 동안 별이 9,275개 늘었고, 지난 7일 X 언급은 22건이에요.

설치

npx skills add https://github.com/mattpocock/skills --skill grill-with-docs

활용법

  1. 새 기능을 시작하기 전에, 만들 내용을 한두 문단으로 적고 grill-with-docs를 불러 질문에 답해 보세요. 전에는 만들다가 빈틈을 발견했다면, 이제는 코드를 쓰기 전에 빈틈이 드러나요.
  2. 같은 것을 팀마다 다르게 부르는 말(예: 회원 · 사용자 · 계정)이 있으면, 질문 중에 하나로 정해 용어집 파일에 남겨요. 다음 세션의 에이전트도 같은 말을 써요.
  3. 왜 그렇게 정했는지 설명하기 어려운 결정은 ADR로 남겨요. 몇 달 뒤 누가 이유를 물어도 문서를 보면 돼요.

예시 프롬프트

/grill-with-docs <만들려는 기능 설명>을 만들려고 해. 코드와 기존 용어집 · ADR을 먼저 읽고, 애매한 용어와 빠진 경우를 하나씩 질문해 줘.

주의. README는 한 에이전트에 설치 방법을 하나만 쓰라고 해요. 플러그인과 npx를 같이 쓰면 스킬이 두 번씩 들어가요. 용어집 파일 이름은 지금 GLOSSARY.md이고, 예전 이름은 CONTEXT.md예요.

microsoft-foundry

무엇인가

Microsoft Foundry에서 AI 에이전트를 만들고 운영하는 일을 에이전트에게 맡기는 스킬이에요. 샘플로 시작해 컨테이너로 묶고, ACR에 올려 배포하고, 일괄 테스트와 프롬프트 개선까지 이어서 해요. 권한(RBAC), 할당량, 리전별 모델 배포 관리도 다뤄요.

왜 지금

지난주 설치가 75,545건으로 직전 3주 평균 8,693건의 8.7배예요. 누적 설치는 661,244건이에요.

설치

npx skills add https://github.com/microsoft/azure-skills --skill microsoft-foundry

활용법

  1. Azure 포털에서 하나씩 누르던 배포를 말로 시켜요. 전에는 패키징, 레지스트리 업로드, 배포 설정을 각각 했다면, 이제는 한 대화 안에서 이어서 해요.
  2. 배포한 에이전트를 테스트 묶음으로 돌려 보고, 결과를 보며 프롬프트를 고치게 해요.
  3. 운영 중인 에이전트의 추적 기록을 읽혀 문제 원인을 찾게 해요.

예시 프롬프트

microsoft-foundry 스킬로 <샘플 이름> 에이전트를 내 Foundry 프로젝트 <프로젝트 이름>에 배포하고, 테스트 케이스 5개로 결과를 확인해 줘.

주의. Azure 계정과 Foundry 프로젝트가 있어야 쓸모가 있어요. 작업 전에 의존성 점검 스크립트를 돌리고 빠진 것을 설치하며, 환경 설정은 .foundry/agent-metadata.yaml 파일에 둬요.
