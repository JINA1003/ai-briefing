Hallmark

무엇인가

Together AI가 만든 웹 디자인 스킬이다. 모든 제목 위 작은 라벨, 제목 속 한 단어만 색칠하기, 실제로 제출되지 않는 폼 같은 기계적 흔적을 찾아낸다. 점검은 출시를 막는 Floor, 이유를 적으면 넘길 수 있는 Reflex, 막지 않는 Finish 세 단계로 나뉜다. 테마 50개와 프롬프트만으로 설계하는 custom 모드가 있다.

왜 지금

지난주 GitHub 트렌딩에서 별 11,566개를 받았다. 7일 별 증가도 10,163개로 별 상위 저장소 중 세 번째다. 누적 별은 43,923개다.

설치

npx skills add nutlope/hallmark -g

활용법

  1. /hallmark audit ./index.html로 기존 페이지의 문제만 리포트로 받는다. 파일은 바뀌지 않는다.
  2. /hallmark <만들 페이지 설명>으로 새 페이지를 만든다. 테마 세 개를 제안받고 상단 영역부터 렌더해 검토한다.
  3. 브라우저 점검까지 쓰려면 npm i -g puppeteer-core를 깔고 Chrome을 준비한다. 없으면 정적 점검만 돈다.

예시 프롬프트

/hallmark audit <점검할 HTML 파일 경로>

주의. Node 18 이상이 필요하다. 브라우저 점검은 puppeteer-core와 Chrome이 있어야 하고, 없으면 정적 점검만 실행된다. 기존 디자인은 이름을 직접 지정해야만 손댄다.

claude-mem

무엇인가

에이전트가 도구로 한 일을 기록하고, AI 모델로 짧게 요약해 다음 세션 시작 때 필요한 부분을 넣어 준다. 세션 시작, 프롬프트 제출, 도구 실행 전후, 종료 등 6개 지점에 훅을 건다. 기록은 SQLite 전문 검색과 Chroma 벡터 검색으로 찾는다.

왜 지금

지난주 GitHub 트렌딩에서 별 5,852개를 받았다.

설치

npx claude-mem install

활용법

  1. 설치 뒤 Claude Code를 다시 열고 평소처럼 작업한다. 다음 세션 시작 때 관련 맥락이 자동으로 들어온다.
  2. 지난 작업을 찾을 때는 search로 목록을 받고, timeline으로 앞뒤를 보고, get_observations로 고른 항목만 자세히 본다.
  3. 문제가 생기면 npx claude-mem doctor로 진단하고 npx claude-mem repair로 고친다.

예시 프롬프트

claude-mem에서 지난주에 <기능 이름> 관련해 고친 버그 기록을 찾아서, 그때 무엇을 바꿨는지 요약해 줘.

주의. 세션 활동을 모두 기록하는 구조다. <private> 태그 안 내용만 저장에서 빠진다. 설치 때 브라우저 로그인을 하면 호스팅 요약 모델 30일 무료 체험이 시작되고, 끝나면 구독하지 않는 한 내 Anthropic 플랜 사용량을 쓴다. npm install -g claude-mem은 라이브러리만 깔고 훅은 설치하지 않는다.

Superpowers

무엇인가

코딩 에이전트가 바로 코드를 쓰지 않고, 먼저 목적을 묻고 명세로 정리해 확인받게 하는 스킬 묶음이다. 계획은 2~5분짜리 작업으로 쪼개고, 작업마다 새 서브에이전트를 띄워 리뷰하거나 한 세션에서 몰아 실행한다. 스킬은 상황에 맞춰 자동으로 켜진다.

왜 지금

지난주 GitHub 트렌딩에서 별 5,896개, 7일 별 증가 5,015개를 받았다. 누적 별은 310,059개로 오래된 대형 저장소가 다시 오르고 있다.

설치

/plugin install superpowers@claude-plugins-official

활용법

  1. 만들고 싶은 기능을 평소 말투로 설명한다. brainstorming 스킬이 질문을 시작한다.
  2. 설계를 승인하면 워크트리에 새 브랜치가 생기고 계획 문서가 나온다. 계획의 작업 단위가 적당한지 본다.
  3. 세션이 엉뚱하게 흘렀으면 "figure out what went wrong with superpowers in this session"이라고 요청해 진단 스킬을 돌린다.

예시 프롬프트

<만들 기능 설명>을 추가하고 싶어. 바로 코드 쓰지 말고 먼저 질문해서 설계부터 같이 정하자.

주의. TDD 스킬은 테스트보다 먼저 쓴 코드를 지운다. 선택 기능인 visual companion은 버전 정보를 보내며, SUPERPOWERS_DISABLE_TELEMETRY로 끌 수 있다.

ECC

무엇인가

Claude Code를 주 대상으로 한 작업 체계다. 에이전트 71개, 필요할 때만 불러오는 스킬 314개, 명령 98개, 훅, 언어별 규칙, 세션 요약 기억을 담았다. 계획, 테스트, 구현, 리뷰, 검증, 기억의 순환을 의도한다.

왜 지금

지난 7일 중 6일 GitHub 일간 트렌딩에 올랐다. 7일 별 증가는 5,210개다.

설치

npx ecc-universal@2.2.3 install --profile minimal --target claude

활용법

  1. /plan 계열 명령으로 기능 하나를 계획하게 한다. 플러그인으로 깔았다면 /ecc:plan이다.
  2. /context-budget으로 지금 컨텍스트 부담을 확인한다.
  3. 긴 작업은 /save-session으로 저장하고 다음에 /resume-session으로 잇는다.

예시 프롬프트

/context-budget

주의. 플러그인 방식은 설치된 목록 전체를 모델에 보여 주므로 컨텍스트가 든다. 크기가 걱정되면 minimal 프로필로 시작한다. 한 도구에 설치 방식은 하나만 쓴다. 겹치면 스킬과 훅이 중복된다. 공식 저장소와 npm 패키지 외의 미러는 악성 코드가 있을 수 있다고 README가 경고한다. /astra-review는 diff를 OpenAI로 보낸다.

grill-me (Matt Pocock)

무엇인가

계획이나 설계를 두고 에이전트가 질문을 계속 던져, 설계 트리의 모든 갈래가 정해질 때까지 몰아붙인다. 작업 전에 사람과 에이전트의 생각 차이를 없애는 것이 목적이다. 코드 작업에는 용어집과 ADR을 함께 남기는 /grill-with-docs가 더 강한 버전이다.

왜 지금

skills.sh 종합 순위 4위다. 지난 7일 X 언급 81회로 소셜 화제 1위였고, 저장소 7일 별 증가는 5,142개다.

설치

claude plugin install mattpocock-skills@claude-plugins-official

활용법

  1. 저장소마다 한 번 /setup-matt-pocock-skills를 돌려 이슈 트래커, 라벨, 문서 위치를 정한다.
  2. 다음 작업 계획을 적고 /grill-me를 부른다. 직접 불러야만 실행된다.
  3. 코드 변경이라면 /grill-with-docs로 바꿔 결정을 ADR로 남긴다.

예시 프롬프트

/grill-me <이번에 하려는 작업 계획을 몇 줄로>

주의. 플러그인과 skills.sh 방식을 같이 깔면 모든 스킬이 두 번 들어간다. 엔지니어링 스킬은 저장소마다 setup 스킬을 먼저 돌려야 한다.

interfaces (jakubkrehel/skills)

무엇인가

인터페이스 작업용 스킬 모음이다. better-interface는 화면이나 흐름을 접근성, 레이아웃, 문구, 글꼴, 색 기준으로 보고 순위가 매겨진 리포트 하나로 돌려준다. better-accessibility는 WCAG 2.2 기준으로 포커스, ARIA, 폼을 점검한다. interface-review는 브랜치나 PR이 새로 만든 UI 문제를 찾는다.

왜 지금

지난주 GitHub 트렌딩에서 별 1,607개를 받았다.

설치

npx skills add jakubkrehel/skills

활용법

  1. 화면 하나를 정해 better-interface로 순위 리포트를 받는다.
  2. PR을 올리기 전에 interface-review로 이번 변경이 만든 UI 문제만 본다.
  3. variant로 컴포넌트 시안 여러 개를 만들어 비교한다.

예시 프롬프트

better-interface 스킬로 <화면 경로나 컴포넌트>를 점검하고 고칠 순서대로 리포트해 줘.

주의. break와 state-machine은 임시 페이지를 만들므로 끝나고 지워야 할 수 있다. README에 요구 사항과 지원 에이전트 설명은 없다.
