외부 측정 · 보도167년 묵은 수학 난제를 AI와 함께 풀었다는 주장이 나왔다. 그런데 그 증명을 끝까지 읽은 수학자는 아직 없다.

주장한 사람은 Anthropic 소속 정수론자 Levent Alpöge다. 그는 11월 20일 「Claude와 함께 리만 가설의 증명을 찾았다고 믿는다」고 밝혔다.

Nature 보도로 처음 내놓은 증명은 약 1,740만 줄의 코드다. 증명은 논문이 아니라 Lean(컴퓨터가 논리 한 단계씩을 검사하는 형식 증명 언어)으로 쓰였다.

Lean을 통과했다는 것은 틀린 단계가 없다는 뜻이다. 왜 참인지 누군가 이해했다는 뜻은 아니다.

Nature 보도로 11월 21일 Lean FRO와 Mathlib Initiative가 확인했다. 둘은 「코드가 컴파일되고, 표준 리만 가설을 정확히 진술한다」고 함께 밝혔다.

11월 23일 Anthropic과 OpenAI가 각각 VP ≠ VNP 증명을 냈다. P 대 NP 문제의 대수 버전으로, 이것도 아직 사람 검토가 없다.

논리는 기계가 확인했다. 왜 참인지는 아직 아무도 설명하지 못한다.

우리 팀에게는

AI가 낸 결과는 설명이 그럴듯해서가 아니라 테스트를 통과해서 믿는다.

  • AI에게 맡길 함수 하나는 구현 전에 테스트부터 써 달라고 한다.
  • 테스트를 사람이 읽고 빠진 경우를 더한 뒤 구현을 맡긴다.

외부 측정 · 보도AI가 한국 경제를 세 군데로 쏠리게 한다는 경고가 나왔다. 11월 25일 나온 moodmode.ai 카드뉴스다.

카드뉴스는 반도체 의존, 미국에 몰린 AI 연산력, 수도권 집중을 꼽았다. 답으로는 지방 AI 데이터센터를 내놓았다.

2025년 8월부터 2026년 3월까지 데이터센터 전기 사용 1차 기술검토 신청은 736건이다. 그중 522건, 71%가 수도권이었다(기후에너지환경부 자료).

수도권 522건 중 최종 공급 가능 승인을 받은 곳은 10건, 1.9%다. 비수도권은 본심사 29건 중 26건, 89.7%가 통과했다(머니투데이).

학습용 데이터센터는 전기가 있는 지방이 유리하다는 분석도 있다. 응답 속도가 중요한 추론용은 쓰는 사람 가까운 수도권이 유리하다고 본다.

반론도 크다. 머니투데이는 「수도권엔 전기가, 지방엔 고객이 없다」고 정리했다.

카드뉴스의 「AI 연산력 74.5%가 미국」과 「한 곳에 3조 5천억 원 효과」는 확인 안 됨이다. 쏠림은 숫자로 확인되지만, 지방이 답인지는 아직 논쟁 중이다.

스킬을 따로 찾아 까는 일이 줄어든다. Anthropic이 11월 24일 Skills over MCP를 공개 베타로 열었다.

MCP는 AI에 외부 도구를 붙이는 표준 연결 방식이다. 이제 MCP 서버가 도구와 함께 스킬(일하는 법을 적은 지침서)을 실어 보낸다.

도구만 받은 AI는 쓰는 순서를 몰라, 사람이 스킬을 따로 깔아 맞췄다. 서버가 바뀌면 스킬은 낡았다.

새로 나온 세 가지 중 첫째는 서버에 실려 오는 스킬(베타)이다. Claude는 필요할 때만 읽고, 서버가 바뀌면 스킬도 같이 바뀐다.

Tasks는 긴 작업을 서버가 뒤에서 돌리게 한다(정식). Elicitation은 서버가 멈추고 폼이나 링크로 사용자에게 묻게 한다(정식).

Shopify · HubSpot · Atlassian이 스킬을, ZoomInfo가 Tasks를 실었다. GitHub는 에이전트가 저장소를 지우기 전에 저장소 이름을 직접 입력하게 한다.

이제 서버는 도구만이 아니라 쓰는 법과 멈출 자리까지 함께 보낸다.

  5. 5 / 5

    처방은 여섯 갈래

    전략적 마찰, 결정 설계, 행동 모니터링, AI 없이 하는 연습, 업무량, 역할 설계.

    arXiv 2608.23642

의견 · 칼럼「최종 확인은 사람이 하니까 안전하다」는 말이 틀릴 수 있다. 한 논문이 「감독이 감독하는 사람을 망가뜨린다」고 결론 냈다.

저자는 Hugging Face의 Margaret Mitchell · Avijit Ghosh 등이다. 최신 4판은 11월 12일에 올라왔다.

승인 창이 되풀이되면 읽지 않고 누른다(승인 피로). 틀린 제안도 받아들이고(자동화 편향), 오류를 알아볼 감각도 녹슨다(기술 퇴화).

지친 사람은 근거가 매끄럽기만 하면 승인한다. 그 승인이 성공의 증거로 쓰이면, 시스템이 신중한 감독을 부추기지 않게 최적화될 수 있다.

논문은 여섯 갈래를 함께 쓰라고 권한다. 전략적 마찰, 결정 설계, 행동 모니터링, AI 없이 하는 연습, 업무량 · 일정 조정, 역할 설계다.

우리 자리로 옮기면 승인 창이다. 테스트 실행, 파일 읽기, 위험한 삭제가 같은 창으로 뜨면 정작 위험한 한 번을 놓친다.

사람이 최종 확인한다는 말은 그 사람이 아직 읽고 있을 때만 참이다.

우리 팀에게는

승인 창은 되돌리기 어려운 동작에만 뜨게 해 주의를 아낀다.

  • /permissions에서 읽기 · 테스트 명령은 permissions.allow에 넣는다.
  • git push · 삭제 · 배포는 permissions.ask에 두어 매번 묻게 한다.

Google이 2주 만에 다섯 가지를 냈다: 중간 모델, 대신 누르기, 심부름, 말로 코딩

원소 이름은 성능 순서가 아니다. Google은 Gemini 4 모델에 원소 이름을 붙였다.

원자번호가 크다고 더 센 모델이 아니다. 11월 18일 나온 Neon(10)은 Carbon(6)과 Hydrogen(1) 사이의 중간 모델이다.

Carbon은 어렵고 긴 작업을, Hydrogen은 빠른 일상 처리를 맡는다. Google은 Neon이 Carbon보다 작업당 비용이 32% 낮다고 했다.

12월 1일부터 Carbon · Argon API 가격은 두 배가 된다. 100만 토큰당 입력은 $2에서 $4로, 출력은 $10에서 $20으로 오른다.

phone-harness (에이전트가 진짜 휴대폰을 쓰게 하기)

무엇인가

휴대폰 앱 확인은 끝까지 사람 손에 남아 있었다. 웹은 에이전트가 브라우저로 돌지만, 앱 화면은 휴대폰을 들고 넘겨 봐야 했다. phone-harness는 MIT 라이선스 오픈소스 도구다. Claude Code · Codex 같은 에이전트가 실제 휴대폰을 다루게 한다. 스크롤하고, 누르고, 입력하고, 화면을 읽는다. 탈옥도, 휴대폰에 따로 까는 앱도 없다. iPhone은 Mac의 iPhone 미러링 창을 읽고 입력을 보낸다. Android는 USB나 Wi-Fi로 adb(안드로이드 기기를 컴퓨터에서 다루는 공식 도구)를 쓴다.

왜 지금

지난 7일 내내 GitHub 일간 트렌딩에 올랐다. 별은 약 5.9천 개다.

설치

uv tool install --python 3.12 --upgrade --force phone-harness

활용법

  1. 앱 출시 전 문구 점검에, 휴대폰을 들고 화면마다 스크린숏을 찍던 일을 「이 화면까지 가서 문구를 읽어 와」라는 한 줄로 맡기면, 기대 문구와 다른 곳만 표로 받는다.
  2. 「세 번째 화면에서 버튼이 안 눌린다」는 버그 신고를 재현할 때, 에이전트에게 같은 순서로 눌러 보게 하면 재현 단계가 말이 아니라 기록으로 남는다.
  3. iPhone과 Android를 둘 다 확인해야 할 때, 같은 지시를 두 기기에 보내면 두 화면이 어디서 다른지만 추려 받는다.
  4. 처음 붙일 때는 README의 설정 프롬프트를 Claude Code에 그대로 붙이면 설치, 스킬 등록, 연결 안내가 이어지고, 연결이 안 되면 phone-harness doctor ios나 phone-harness doctor android로 점검한다.

예시 프롬프트

phone-harness로 내 iPhone에서 <앱 이름>을 열고 <화면 이름>까지 가서 화면 문구를 읽어 줘. 결제, 메시지 보내기, 설정 바꾸기는 하지 말고, 화면 문구가 <기대 문구>와 다른 곳만 표로 정리해 줘.

주의. 에이전트가 진짜 휴대폰을 다룬다. iPhone은 macOS 15 이상과 iOS 18 이상, iPhone 미러링 연결, 명령을 돌리는 앱의 손쉬운 사용 · 화면 기록 권한이 필요하다. 넓은 macOS 권한이니 그 앱에만 준다. iPhone을 직접 잠금 해제하면 미러링이 멈추고, PIN으로 잠긴 Android는 사람이 풀어야 한다. 글자만 읽어서 이름 없는 아이콘은 스크린숏과 그림을 읽는 모델이 필요하다. 멀티터치, 카메라, Face ID는 안 되고 DRM 영상은 검게 나온다. 사용 기록(텔레메트리)이 기본으로 켜져 있다. 클라우드 기기는 유료다(iPhone 월 $80부터, Android 분당 5센트).

Orca (코딩 에이전트 여럿을 한 앱에서)

무엇인가

에이전트를 두 개 넘게 돌리면 어느 터미널 탭이 무슨 일을 하는지부터 헷갈린다. Orca는 MIT 라이선스 오픈소스 데스크톱 앱이다. Claude Code · Codex 같은 코딩 에이전트를 내 구독 그대로 여러 개 나란히 돌린다. 작업마다 따로 worktree(같은 저장소를 폴더 여러 개로 나눠 여는 git 기능)를 만든다. 그래서 에이전트끼리 부딪히지 않는다. Slack · Linear · GitHub나 휴대폰에서 봇에게 일을 맡길 수 있다. 봇은 테스트를 거친 PR로 돌려준다.

왜 지금

지난 7일 별이 6,224개 늘었다(현재 약 14만 개). 11월 21일 판에서 봇이 Gemini CLI · Goose 등 에이전트 8개 위에서도 돌게 됐다. 11월 22일 판에서는 여러 컴퓨터의 봇을 한 그룹에 묶게 됐다. 휴대폰 앱에서 끝까지 관리하게도 됐다.

설치

brew install --cask stablyai/orca/orca

활용법

  1. 며칠 걸리는 리팩터링을 여러 갈래로 나눌 때, 탭마다 Claude Code를 띄우던 것을 작업마다 worktree를 둔 에이전트로 바꾸면 한 화면에서 진행 상태를 칸반 보드처럼 본다.
  2. 급하지 않은 버그 티켓이 쌓일 때, Slack이나 Linear에서 봇에게 「이 버그 고쳐 줘」라고 맡기면 테스트를 거친 PR로 돌아와 나는 리뷰만 한다.
  3. 에이전트가 낸 diff를 볼 때, 고칠 줄에 메모를 달면 그대로 에이전트에게 가서 다시 설명하는 수고가 준다. 자리를 비웠을 때는 휴대폰 앱의 「Needs you」에서 승인과 질문에 답한다.
  4. 매일 반복하는 점검은 평일 정해진 시각, PR 열림, 검사 실패 같은 조건에 봇을 걸어 두면 사람이 기억하지 않아도 돈다.

예시 프롬프트

로그인 뒤 프로필 사진이 바뀌지 않는 버그를 고쳐 줘. 원인을 먼저 한 줄로 설명하고, 고친 뒤 관련 테스트를 돌려 통과 결과와 함께 PR로 올려 줘.

주의. 봇은 내 Claude Code · Codex 구독으로 돌아서 요금과 한도는 그 구독을 따른다. Homebrew에서 그냥 orca는 관계없는 Plotly 앱이니 전체 이름을 쓴다. 익명 사용 통계를 모으며 끌 수 있다. 봇의 성격 · 기억은 SOUL.md · MEMORY.md 평문 파일에 남는다. 봇에 Slack · GitHub를 연결하기 전에 orca.dev의 봇 보안 문서를 읽는다.

CLI-Anything (아무 앱이나 에이전트가 부르는 명령줄로)

무엇인가

에이전트에게 화면 있는 프로그램을 맡기면 결국 화면을 눌러야 한다. 그래서 느리고 자주 틀린다. CLI-Anything은 Apache-2.0 라이선스 Claude Code 플러그인이다. 기존 소프트웨어의 소스 코드를 분석해 에이전트가 부를 수 있는 명령줄 도구(CLI)를 만든다. 만드는 과정은 7단계다. 만든 CLI는 JSON 출력과, 에이전트가 찾아 쓰는 SKILL.md를 갖춘다. 이미 만들어 둔 CLI는 CLI-Hub에서 받아 바로 쓴다.

왜 지금

지난 7일 중 5일 GitHub 일간 트렌딩에 올랐다. 별은 약 6.6만 개다.

설치

/plugin marketplace add HKUDS/CLI-Anything

활용법

  1. 다른 팀에 넘길 문서 수십 개를 PDF로 바꿀 때, 하나씩 열어 저장하던 일을 CLI-Hub의 LibreOffice CLI로 에이전트에게 맡기면 명령 한 번으로 끝나고 같은 일을 다시 시켜도 결과가 같다.
  2. 그림 크기 맞추기 · 워터마크 같은 반복 편집에, 화면 자동화 대신 GIMP용 CLI를 쓰게 하면 에이전트가 버튼 위치가 아니라 명령으로 일해 덜 틀린다.
  3. 소스가 있는 사내 도구는 /plugin install cli-anything 뒤 /cli-anything <소스 경로>로 전용 CLI를 만들면, 에이전트가 그 도구를 JSON 결과로 읽고 다룬다.
  4. 한 번에 기능을 다 덮지 못하면 /cli-anything:refine <경로>로 빈 곳을 채우고, /cli-anything:test <경로>로 테스트를 돌려 결과를 TEST.md에 남긴다.

예시 프롬프트

CLI-Hub에서 LibreOffice용 CLI가 있는지 찾아 설치해 줘. 있으면 그 CLI로 <폴더>의 .docx 파일을 모두 PDF로 바꿔 줘. 실행 전에 어떤 명령을 쓸지 먼저 보여 줘.

주의. README는 최상위급 모델을 쓰라고 하고, 작은 모델은 불완전하거나 틀린 CLI를 만들 수 있다고 적었다. 소스 코드 없이 실행 파일만 있으면 품질이 크게 떨어진다. 한 번 실행으로 기능을 다 덮지 못해 refine을 여러 번 돌려야 할 때가 많다. GIMP · LibreOffice 같은 원래 앱은 따로 설치해야 한다.

AI 브라우저가 뭔지부터: ego lite · Aside · Handlus를 같은 기준으로 비교

보통 브라우저는 사람이 누른다. AI 브라우저는 AI 에이전트가 페이지를 읽고, 버튼을 누르고, 칸에 입력한다. 「다음 주 회의실 예약」 「거래처 열 곳 정보 모으기」를 말로 맡긴다. 그러면 에이전트가 그 사이트를 직접 돈다. 방식은 두 갈래다. Claude in Chrome 같은 확장은 내가 쓰던 크롬에 에이전트를 붙인다. 로그인 상태를 그대로 쓰지만, 에이전트와 내가 같은 브라우저를 나눠 쓴다. AI 브라우저는 브라우저 자체를 에이전트에 맞게 다시 만든 것이다. 에이전트마다 따로 공간을 주거나, 비밀번호를 AI에게 보이지 않고 넣어 준다. 대신 브라우저를 옮겨야 한다. 아래에서 셋을 같은 기준으로 놓았다. 기준은 어떤 방식인지, 지원 운영체제, 쓰던 브라우저를 그대로 두는지다. 비밀번호 처리, 무료 한도, 유료 가격, 확인 여부도 본다.

설치 · 설정

npx skills add citrolabs/ego-lite
  1. 기준선, Claude in Chrome (Anthropic 공식 확장): 내 크롬에 붙는 확장이다. Chrome · Edge를 지원하고 다른 Chromium 브라우저도 감지한다. 쓰던 브라우저와 로그인 상태를 그대로 쓰고, 로그인 화면 · CAPTCHA가 나오면 멈추고 사람에게 넘긴다. Pro · Max · Ultra · Team · Enterprise 플랜에서 쓰고, Claude Code에서는 claude --chrome으로 켠다. 확인함(공식 문서).
  2. ego lite (citrolabs): 사람과 에이전트가 같이 쓰는 Chromium 기반 별도 브라우저다. Claude Code · Codex 등이 ego-browser 스킬로 조작하고, 에이전트마다 따로 떨어진 Space를 줘서 여러 일을 동시에 돌린다. macOS · Windows를 지원하고 Linux는 계획이다. 브라우저를 옮겨야 하며, 첫 실행 때 크롬 로그인 · 쿠키 · 확장을 옮길지 묻는다. 에이전트는 지금 보는 페이지 내용을 내가 고른 모델에 보낸다. 앱은 무료이고 모델 비용은 따로다. 속도 수치는 업체 자체 시험(31개 작업)이다. 확인함(README · 공식 페이지).
  3. Aside: 사람과 에이전트를 위해 다시 만든 브라우저다. macOS 15 이상, Windows 10(22H2) 이상 · 11을 지원하고, 브라우저를 옮겨야 한다. 비밀번호는 자동 입력으로 넣되 AI에게 원문을 보여 주지 않고, 결제 · 게시 · 메시지는 내 확인을 기다리며, 비밀번호를 쓸 때마다 기록한다. 무료는 월 500크레딧(내 ChatGPT · Claude 구독이나 API 키를 연결), Pro 월 $20, Max 월 $200이다. 컴퓨터 프로그램 조작(computer use)이 모든 요금제에 열리는지 Max 전용인지는 출처마다 다름(공식 가격 페이지에 언급 없음).
  4. Handlus: 돌고 있는 소개 이미지에 따르면 크롬 · 엣지 · 웨일 확장과 Mac · Windows · Linux 데스크톱 앱이 있고, MCP로 Claude Code · Codex에 연결된다. 무료는 주 1,500회 요청 · 컴퓨터 조작 300회, Pro는 월 $20이라고 한다. 공식 사이트를 웹에서 찾지 못해 이름 · 주소 · 가격 모두 확인 안 됨.
  5. 누구에게 무엇: Claude Code만 쓰고 쓰던 크롬을 그대로 두고 싶으면 Claude in Chrome. 돈 들이지 않고 에이전트 여러 개로 동시에 일을 돌리려면 ego lite. 로그인이 많은 사이트를 맡기고 비밀번호를 AI에게 보이기 싫으면 Aside. Handlus는 공식 정보가 확인되면 다시 본다.

실습

ego lite에서 Claude Code에게 웹 조사 하나를 맡겨, 내 탭과 따로 도는지 본다.

  1. lite.ego.app에서 ego lite 앱을 내려받아 설치한다. 크롬 데이터 옮기기는 필요한 것만 고른다.
  2. 터미널에서 npx skills add citrolabs/ego-lite로 ego-browser 스킬을 깐다.
  3. Claude Code에서 아래 두 번째 프롬프트를 넣는다.
  4. 에이전트가 자기 Space에서 일하는 동안 내 탭을 그대로 쓸 수 있는지 본다.
  5. 같은 일을 claude --chrome으로도 해 보고 둘을 비교한다.

바로 쓰는 프롬프트

어떤 AI 브라우저가 맞는지 고르기

나는 <주로 맡길 웹 일>을 AI에게 맡기고 싶어. 쓰는 운영체제는 <OS>, 지금 쓰는 브라우저는 <브라우저>야. Claude in Chrome, ego lite, Aside 중 무엇이 맞는지 비밀번호 처리와 비용을 기준으로 골라 주고, 확인되지 않은 정보는 확인되지 않았다고 표시해 줘.

ego-browser로 조사 맡기기

ego-browser로 <조사할 주제>에 대해 <사이트 세 곳>을 돌며 정보를 모아 표로 정리해 줘. 로그인이나 결제가 필요한 화면이 나오면 멈추고 나에게 물어봐.

Claude in Chrome으로 내 화면 확인하기

<내 웹앱 주소>를 열고 <기능 이름>을 직접 눌러 확인해 줘. 콘솔 오류가 있으면 메시지를 그대로 옮기고, 아무것도 저장하거나 보내지는 마.

안 될 때

Claude Code에서 크롬 연결 중 「Receiving end does not exist」가 뜬다.
확장의 서비스 워커가 쉬는 상태다. /chrome을 실행하고 「Reconnect extension」을 고른다.
--chrome을 붙였는데 크롬 연동이 켜지지 않는다.
API 키나 claude setup-token 토큰으로 로그인하면 꺼진 채로 남는다. /login으로 Claude 플랜 계정에 로그인하고, 확장도 같은 조직 계정으로 로그인한다.

주의. AI 브라우저는 로그인된 사이트에서 실제로 누르고 입력한다. 결제 · 게시 · 메일 발송 앞의 승인 단계는 끄지 않는다. ego lite는 지금 보는 페이지 내용을 고른 모델로 보낸다. Claude in Chrome의 GIF 녹화에는 화면에 보이는 계정 정보가 찍힌다. 속도 · 성공률 수치는 모두 업체 자체 시험이다.
