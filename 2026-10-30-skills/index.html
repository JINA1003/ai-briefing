security-audit (Cloudflare)

무엇인가

코딩 에이전트에게 보안 감사를 맡기는 스킬이다. 정찰, 커버리지 기반 탐색, 후보 검증, 구조화 출력, 독립 재검증, 보고서 작성의 6단계를 서로 분리된 에이전트가 맡는다. 결과는 findings.json에 confirmed, needs_validation, rejected 세 판정으로 남고, 사람이 읽을 Markdown 보고서 세 개가 함께 나온다.

왜 지금

지난주 설치가 16,762회로 직전 3주 평균 6,319회의 2.7배다. 같은 주 GitHub 스타도 14,320개 늘었고, 누적 설치는 66,758회다.

설치

npx skills add https://github.com/cloudflare/security-audit-skill --skill security-audit

활용법

  1. 작은 사내 저장소에서 "security audit this codebase"라고 요청해 전체 감사를 한 번 돌린다.
  2. ~/security-audit-skill/<repo-name>/run-<N>에 생긴 REPORT.md와 NEEDS-VALIDATION.md를 읽고, 남은 미확정 항목을 직접 확인한다.
  3. 같은 저장소에 한 번 더 돌려 앞선 결과 위에 새로 찾은 항목이 붙는지 본다.

예시 프롬프트

security audit this codebase. 인증과 외부 입력을 받는 경로를 중심으로 보고, 결과 보고서 위치를 알려 줘.

주의. 병렬 서브에이전트를 쓰는 에이전트와 Node.js가 필요하다. 대상 코드를 실행하려면 외부 네트워크를 막는 OS 수준 샌드박스가 있어야 하고, 없으면 코드를 실행하지 않고 needs_validation으로 남긴다. Cloudflare 테스트에서 한 번 실행은 반복 실행이 찾은 취약점의 대략 절반을 찾았다. README에 비용·토큰 사용량 안내는 없다.

grill-me (Matt Pocock)

무엇인가

계획이나 설계를 두고 에이전트가 질문을 계속 던져, 설계의 갈래가 모두 정해질 때까지 몰아붙이게 하는 스킬이다. 사용자가 /grill-me를 입력할 때만 실행된다. README는 이 스킬을 코드 밖의 일에 쓰라고 하고, 코드 작업에는 GLOSSARY.md와 ADR까지 갱신하는 /grill-with-docs를 권한다.

왜 지금

이번 주 상위 20에 4위로 새로 들어왔다. 지난 7일 X 언급 77회로 소셜 화제 1위다.

설치

claude plugin install mattpocock-skills@claude-plugins-official

활용법

  1. 설치한 뒤 쓰려는 저장소에서 /setup-matt-pocock-skills를 한 번 실행한다.
  2. 다음 작업 계획을 몇 줄로 적고 /grill-me로 질문을 받아 본다.
  3. 코드 변경 계획이라면 /grill-with-docs로 바꿔 GLOSSARY.md와 ADR이 갱신되는지 확인한다.

예시 프롬프트

/grill-me 이번 주에 주간 보고서 자동 생성 파이프라인을 만들려고 해. 입력은 후보 JSON, 출력은 HTML 한 장이야.

주의. 플러그인과 npx 설치를 같은 에이전트에 함께 하면 모든 스킬이 두 번 잡힌다. 하나만 고른다.

agent-browser (Vercel Labs)

무엇인가

AI 에이전트가 브라우저를 조작하게 해 주는 Rust 기반 CLI다. 페이지를 접근성 트리 스냅샷으로 읽고, @e2 같은 짧은 참조로 요소를 클릭하거나 입력한다. 스킬 파일은 안내 역할만 하고, 실제 사용법은 설치된 CLI에서 agent-browser skills get core로 불러온다.

왜 지금

이번 주 상위 20에 2위로 새로 들어왔다. 지난 7일 X 언급은 78회다.

설치

npx skills add https://github.com/vercel-labs/agent-browser --skill agent-browser

활용법

  1. CLI를 따로 설치한다. README의 전역 설치는 npm install -g agent-browser 다음 agent-browser install(처음 한 번 Chrome 내려받기)이다.
  2. 로컬 개발 서버를 open으로 열고 snapshot -i --json으로 상호작용 요소의 참조를 받아 본다.
  3. --allowed-domains로 접근할 도메인을 제한한 채 로그인 폼 채우기를 시켜 본다.

예시 프롬프트

agent-browser로 http://localhost:3000 을 열고, 회원가입 폼을 채워 제출한 뒤 결과 화면의 스크린샷을 남겨 줘.

주의. 보안 기능은 모두 기본으로 꺼져 있다. 상태 파일에는 세션 토큰이 평문으로 저장되므로 .gitignore에 넣거나 AGENT_BROWSER_ENCRYPTION_KEY로 암호화한다. 페이지에서 온 출력은 신뢰할 수 없고, 경계 표시는 프롬프트 주입 방어가 아니다.

Impeccable

무엇인가

코딩 에이전트에게 디자인 명령 24개를 주는 스킬이다. bolder, quieter, polish 같은 명령은 한 가지 디자인 수정을 위한 지침을 불러오고, critique와 audit는 점수와 P0~P3 우선순위가 붙은 검토를 낸다. LLM 없이 규칙 62개로 도는 슬롭 검출기도 들어 있다.

왜 지금

이번 주 GitHub 스타가 9,713개 늘었다.

설치

npx impeccable install

활용법

  1. 프로젝트 루트에서 설치하고 도구를 다시 불러온 뒤 /impeccable init으로 PRODUCT.md를 만든다.
  2. 이미 있는 화면 하나에 critique를 돌려 점수가 붙은 검토를 받는다.
  3. npx impeccable detect를 CI나 로컬에서 돌려 슬롭 규칙 위반을 확인한다.

예시 프롬프트

/impeccable critique 설정 페이지(src/pages/settings.tsx)를 검토하고, 가장 큰 문제 세 개를 고쳐 줘.

주의. 새 페이지를 처음부터 만드는 것보다 이미 있는 화면을 다듬는 데 강하다. Claude Code에서는 모델의 명령을 거부해도 훅은 실행되어 첫 편집 때 엔진을 내려받을 수 있으니, 무인 실행 전에 훅을 검토한다. 라이브 모드는 로컬 체크아웃에서만 쓴다.

Claude SEO

무엇인가

웹사이트를 감사해 우선순위가 붙은 조치 계획을 내는 Claude Code 플러그인이다. 기술 SEO, Core Web Vitals, 콘텐츠 품질, Schema.org, AI 검색 인용 가능성까지 다룬다. 사업 유형을 판별한 뒤 최대 17개 에이전트를 병렬로 돌리고, 보고서는 Markdown으로 저장한다.

왜 지금

이번 주 GitHub 스타가 4,110개 늘었다.

설치

/plugin marketplace add AgriciDaniel/claude-seo

활용법

  1. 마켓을 추가한 뒤 /plugin install claude-seo@agricidaniel-claude-seo로 설치하고 /seo setup을 실행한다.
  2. 전체 감사 전에 /seo page <url>로 한 페이지만 먼저 돌려 본다.
  3. /seo doctor로 설치 상태를 확인하고, 필요하면 /seo google setup으로 무료 Google API를 연결한다.

예시 프롬프트

/seo page https://example.com/pricing

주의. Claude Code 1.0.33 이상과 Python 3.11~3.14가 필요하다. 전체 감사는 Opus 에이전트 5개가 돌아 단일 페이지 검사보다 플랜 사용량이 많다. 분석하는 페이지 내용은 Anthropic Claude로 전송된다. Google 키가 없으면 Core Web Vitals는 실험실 추정치다.

Taste Skill

무엇인가

코딩 에이전트가 흔한 AI 랜딩 페이지 대신 아트 디렉션이 있는 화면을 만들게 하는 스킬이다. 브리프 읽기, 디렉션 선택, 핵심 아이디어, 공개 이미지 수집, 브라우저 검사, 자체 검토의 6단계를 거친다. 2.1부터 대시보드와 앱 화면을 위한 별도 경로가 생겼다.

왜 지금

이번 주 GitHub 스타가 4,359개 늘었다.

설치

npx skills add https://github.com/Leonxlnx/taste-skill --skill "design-taste-frontend"

활용법

  1. Node 22 이상과 Chrome 계열 브라우저가 있는지 확인한다.
  2. 버려도 되는 브랜치에서 소개 페이지 하나를 만들게 하고, 세 가지 화면 폭 검사 결과를 본다.
  3. 대시보드 화면 하나를 앱 경로로 만들게 해 숫자 정렬과 색 사용을 확인한다.

예시 프롬프트

design-taste-frontend 스킬로 사내 도구 소개 페이지를 만들어 줘. 대상은 개발자, 핵심은 설치 3단계야.

주의. 한 번 만드는 데 30~45분, 수십만 토큰이 든다. 이미지 검색에 인터넷이 필요하고, 공개 아카이브 이미지는 자리표시용이라 실제 자료로 바꿔야 한다.
